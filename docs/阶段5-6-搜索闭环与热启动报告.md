## 3. 单场景闭环结果（100 km，俯仰 3°/20 s/起点 t=10 s，60 s）

| 组 | rmse (°) | peak (°) | γ_max (°) | σ_min | \|H\|max | 残差 | 回退 | 超时 | 控制耗时 均值/最大 (ms) | 搜索耗时 均值/最大 (ms) |
|---|---|---|---|---|---|---|---|---|---|---|
| A 仅舵面 | 0.096 | 0.254 | 0 | 40.82 | 0.0 | 0.000 | 0 | 0 | 0.3 / 1.1 | — |
| B 舵面+CMG | 0.096 | 0.250 | 57.2 | 22.14 | 48.5 | 0.000 | 0 | 0 | 0.3 / 1.3 | — |
| C 每周期有界 A\* | 0.096 | 0.250 | 57.2 | 22.14 | 48.5 | 0.000 | **20** | **5** | 69.9 / **148.9** | 59.8 / 73.8 |
| D 热启动+局部修复 | 0.096 | 0.251 | 51.9 | 25.21 | 45.4 | 0.000 | 0 | 0 | 69.1 / 127.9 | 59.0 / 69.3 |
| D（修复预算 20%） | 0.096 | 0.251 | 51.9 | 25.21 | 45.4 | 0.000 | 0 | 0 | 32.9 / 109.4 | **22.9** / 56.3 |

D 组统计：`reuse_hits=298, repairs=1, full_replans=1, invalid_paths=0, reuse_rate=0.993`；
修复预算 20% 时 `reuse_hits=299, reuse_rate=0.997`，轨迹与 80% 完全相同。

### 3.1 结论（正面与负面都列）

1. **本场景下 A/B/C/D 的姿态指标几乎相同**（rmse 0.096°）。原因在阶段 4 已量化：机动需求峰值
   只有 10.1 N·m，而 CMG 保证力矩 61.2 N·m，构型怎么摆都够用。**搜索在本场景没有增量价值**，
   这是物理结论，不是实现缺陷。
2. **C 组（每周期重搜）反而变差**：5 次超时 + 15 次"路径未通过精确复核"→ 共 20 次进入安全回退，
   期间停止构型迁移。这是有界搜索在 200 ms 周期下的真实代价。
3. **D 组把这 20 次回退降为 0**：历史路径复核通过即复用，只在严格更优时替换。
   代价是 `γ_max` 从 57.2° 降到 51.9°、`|H|max` 从 48.5 降到 45.4 N·m·s（瞬时差异，不是"更好"的证据）。
4. **历史复用没有降低单次搜索耗时**（热 76.8 ms vs 冷 56.1 ms，见 W5）：因为 §7.2 要求把
   80% 预算继续用于路径附近的更优解搜索。**只有把修复预算降到 20% 才看到耗时收益**
   （59.0 → 22.9 ms，最坏 56.3 ms）。这条敏感性数据会用于阶段 7/8 冻结配置。
5. **实时裕量不足**：C 组最坏 148.9 ms / 200 ms（1.34× 裕量），D 组 127.9 ms。按 §11，
   必须在阶段 7 前减小图规模或层数，不能靠放宽物理约束换速度。

## 4. 测试结果（`tests/test_warm_start.py`，4/4）

| # | 验收项 | 结果 |
|---|---|---|
| W1 | 路径能接续真实当前状态 | 平移 3 片后首节点与当前量化构型一致；构型偏移 10° 时正确重锚；偏离 ±85° 时判 `cannot-join:gdot_max`（**不硬接**） |
| W2 | 受影响代价可更新 | 同一路径在 t=10 s 用当周期需求重算（返回 `incumbent.cost`），不存在沿用旧代价 |
| W3 | 失效路径能修复或重搜 | 破坏第 1 步后仍返回 `warm`/`verified=True`；重搜次数受限（`max_full_replans`） |
| W4 | 未验证旧路径不会执行 | 越行程历史路径 `valid=False`，`status=budget`，下发 `\|γ̇_ref\|=0.000` |
| W5 | 复用耗时变化可量化 | 冷 56.1 ms / 热 76.8 ms（均值），并说明收益在**避免回退**而非缩短单次耗时 |

## 5. 失败项与剩余风险

| 编号 | 问题 | 计划 |
|---|---|---|
| R1 | C 组 5% 周期出现"筛选层通过、精确 QP 复核失败"（15/300） | 支撑函数是方向性上界，不保证可加可达；已按 §7.3 只在复核通过时下发。若要降比例，可把复核下沉到每条候选边（代价 +1 ms/边，当前预算不允许） |
| R2 | 实时裕量 1.34×（C）/1.56×（D） | 阶段 7 前把 `horizon_s` 或 `step_s` 收敛到最坏 ≤ 80 ms |
| R3 | 修复预算比例尚未冻结 | 已有 80%/20% 两组数据；正式对照前按 §6"看结果后不得只留最有利参数"的要求，用阶段 7 的边界场景重新测一次再冻结 |
| R4 | 场景不触及能力边界 | 阶段 7 可行性扫描的**首要**任务 |
