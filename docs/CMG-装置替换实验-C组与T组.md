# 把 C 组 / T 组改用 CMG 重做（不再使用反作用轮）

**问题：** 原来的 C0–C4（俯仰任务）与 T1/T3（三轴任务）是用**反作用轮**做的。
动量交换装置统一换成 **CMG** 之后效果如何？如果 CMG 会发散，怎么调才不发散？

**做法：** 保留两组任务的原始场景与控制器结构，装置固定为 CMG，只在
"控制器结构"和"任务难度"两个维度上做实验。

```bash
python scripts/run_device_sweep.py --all --jobs 4     # 12 次运行
python scripts/plot_device_sweep.py
```

代码：`nearspace/arms.py`、`scripts/run_device_sweep.py`、
`configs/cmg_ab/device_sweep.yaml`。数据：`results/cmg_ab/device_sweep/`。

> 反作用轮已弃用：其代码与数据保存在 `legacy/` 与 `results/legacy_rw/`，
> 本流程不再包含任何轮子装置。

---

## 1. 实验臂与场景

| 组 | 场景 | 时长 |
|---|---|---|
| `cseries`（C0–C4） | 100 km 顶点，俯仰 **5° 余弦脉冲** @105 s / 10 s | 200 s |
| `tseries`（T1/T3） | 100 km 顶点，**5° 俯仰 + 5° 滚转 + 3° 偏航**余弦脉冲 @110 s / 20 s | 150 s |

| 臂 | 装置 | 控制器 |
|---|---|---|
| `C1` / `T1` | 无（`cmg_on=False`，18 状态模型中断开 CMG：框架冻结、力矩与角动量恒零） | 统一 MPC |
| `C3` / `T3` | **CMG**（4 单元金字塔，50 N·m·s/单元，γ̇≤1.5 rad/s，力矩盒 61 N·m，动量预算 60 N·m·s） | 统一 MPC（决策量 = `[δ_c, M_cmg]`） |
| `C0` | CMG，真值与控制器同为 10 ms 框架滞后（标称 30 ms），用于性能上界 | 统一 MPC |
| `C2` | CMG | **分层**：力矩层 MPC + 伪逆操纵律分配 + 零运动 |
| `C4` | CMG | 统一 MPC，但控制器气动系数偏 20%（真值仍标称） |

`C1/T1` 用的是同一个 18 状态模型的 `cmg_on=False` 分支，所以"无装置"与
"有 CMG"只差装置本身，不是两套模型。

## 2. C 组结果（俯仰 5° 脉冲 @105 s / 10 s，200 s）

| 臂 | 控制器 | 三轴 RMSE [°] | 峰值 [°] | 俯仰 RMSE [°] | 舵面峰值 [°] | CMG 峰值力矩 [N·m] | CMG 峰值角动量 [N·m·s] | σ_min | QP 失败 |
|---|---|---|---|---|---|---|---|---|---|
| `C0` | 统一（10 ms 滞后） | **0.4446** | 2.633 | 0.4446 | 20.48 | 6.82 | 11.76 | 37.97 | 0 |
| `C1` | 仅舵面 | 0.4706 | 2.647 | 0.4705 | 24.25 | 0 | 0 | 40.82 | 0 |
| `C2` | **分层分配** | **91.98（发散）** | 179.8 | 23.10 | 25（饱和） | 116.3 | **74.89** | **4.12** | 0 |
| `C3` | 统一 MPC | **0.4449** | 2.614 | 0.4448 | 20.97 | 7.15 | 11.03 | 38.55 | 0 |
| `C4` | 统一 + 气动失配 20% | 0.4548 | 2.640 | 0.4548 | 20.34 | 6.29 | 9.38 | 38.55 | 0 |

### 读数

1. **控制结构的影响远大于装置本身**：同一个 CMG，分层"力矩层 MPC + 伪逆分配"
   发散到 92°，统一 MPC 稳在 0.445°。原因很清楚——分层方案的规划层不知道
   `σ_min(A)` 与可交付力矩包线（`|UᵀM| ≤ 0.8σ_i√n γ̇max`），把 CMG 推进了近奇异区
   （σ_min 掉到 **4.12**，下限 12.25），指令力矩交付不出来，于是越纠越偏。
   **这就是 C 组原本要证明的事：统一 MPC（把执行机构的真实约束放进 QP）才是
   让 CMG 可用的前提。**
2. **C0 上界只比 C3 快 1.5%**（0.4446 vs 0.4449）：在这条任务上瓶颈不是框架滞后。
3. **C4 的 20% 气动失配只增加 2.2% 误差**（0.4449 → 0.4548）：统一 MPC 的反馈
   加上 CMG 的权限把气动模型误差吸收了。
4. **注意这条任务的物理性质**：5°/10 s 需要峰值力矩 ≈146 N·m、角动量 ≈233 N·m·s，
   而气动只有 20 N·m、CMG 力矩盒 61 N·m——**任何执行机构组合都跟不上这个参考**。
   所以 C 组测的其实是"在跟不上的参考下能把扰动吸收到多小"，不是跟踪能力。
   C1（0.4706）与 C3（0.4449）只差 5.5%，正说明这一点。

## 3. T 组：先看满幅为什么会发散

满幅 5°/5°/3°、Tm = 20 s 的**理论角动量需求**（余弦脉冲，峰值角速率 = πΔθ/Tm）：

| 轴 | Δθ | 峰值角速率 | 需求角动量 J·ω |
|---|---|---|---|
| 俯仰 | 5° | 0.0137 rad/s | **116.5 N·m·s** |
| 偏航 | 3° | 0.0082 rad/s | 74.0 N·m·s |
| 滚转 | 5° | 0.0137 rad/s | 16.4 N·m·s |
| 合成 | | | **139.0 N·m·s** |

对照 CMG 的能力：控制器预算 **60**、单轴（俯仰）硬件可用 **107.7**、集群 200。
**单是俯仰一项的 116.5 就超过了单轴硬件可用量 107.7**——满幅 T 组任务超出了
CMG 的**硬件**能力，不只是控制器预算。

| | T1（仅舵面） | T3（CMG） |
|---|---|---|
| 三轴 RMSE | 1.547° | **19.38°（发散到 88°）** |
| 滚转/俯仰/偏航 RMSE | 0.720 / 0.621 / 1.232 | **18.39** / 4.00 / 4.82 |
| CMG 峰值角动量 | 0 | **63.69（打穿 60 预算）** |
| σ_min | 40.82 | **7.25（下限 12.25）** |
| QP 未收敛 / 回退 | 0 | **137** |

**机理：** 发散主要发生在**滚转**轴（RMSE 18.4），而滚转的需求只有 16.4 N·m·s。
所以不是滚转的动量不够，而是：CMG 为了在俯仰+偏航上持续出力，框架角被推到
σ_min 只剩 7.25 的位形，**滚转方向的权限随之丢失**；100 km 处滚转又几乎没有
气动阻尼，误差就单向累积。这正是"金字塔构型在持续力矩下必然穿越奇异面"
（`docs/CMG-实现状态.md` §7）在三轴任务上的表现。

## 4. 怎么调才让 CMG 不发散：两种等效做法 + 一个无效做法

**判据（可直接用）**：逐轴需求 `J·π·Δθ/Tm` 必须低于 CMG 单轴可用角动量
（107.7 N·m·s），并且留 ≥25% 余量 → 目标 **≤ ~80 N·m·s/轴**。
三轴合成需求对应 ≲ 95 N·m·s。

### 做法一：缩短幅度（Tm 不变）

| 工况 | 幅度 | 理论需求 | T1 RMSE | T3 RMSE | **CMG 改善** | T3 \|H\|max | σ_min | QP 失败 |
|---|---|---|---|---|---|---|---|---|
| `tseries` | 5 / 5 / 3° | 139 | 1.547 | 19.38 | 发散 | 63.7 | 7.25 | 137 |
| `tseries_s60` | 3 / 3 / 1.8° | 83 | 0.7389 | **0.3516** | **−52.4%** | 19.6 | 37.81 | 0 |
| `tseries_s40` | 2 / 2 / 1.2° | 56 | 0.3318 | **0.2822** | −14.9% | 8.08 | 37.81 | 0 |
| `tseries_s25` | 1.25 / 1.25 / 0.75° | 35 | 0.1686 | **0.1575** | −6.6% | 2.19 | 37.81 | 0 |

### 做法二：拉长机动时间（幅度不变）——**推荐**

同样做 5°/5°/3°，只把 Tm 从 20 s 拉到 30/40 s，需求按 1/Tm 下降：

| 工况 | Tm | 理论需求 | 俯仰轴需求 | T1 RMSE | T3 RMSE | **CMG 改善** | T3 \|H\|max | σ_min | QP 失败 |
|---|---|---|---|---|---|---|---|---|---|
| `tseries` | 20 s | 139 | 116.5 | 1.547 | 19.38 | 发散 | 63.7 | 7.25 | 137 |
| `tseries_t30` | **30 s** | 93 | **77.7** | 0.9279 | **0.4655** | **−49.8%** | 25.63 | 37.81 | 0 |
| `tseries_t40` | **40 s** | 70 | **58.2** | 0.4932 | **0.3207** | **−35.0%** | 16.06 | 37.81 | 0 |

`Tm = 30 s` 是保留原幅度、让 CMG 稳定工作的最小机动时间：俯仰轴需求 77.7
低于单轴硬件 107.7 且有余量，CMG 只用了 25.6 N·m·s（预算的 43%），
σ_min 保持在 37.81（远高于下限 12.25），**三轴 RMSE 从 0.9279° 降到 0.4655°（−50%）**。

### 无效做法：放宽动量预算

| 工况 | 预算 | T1 RMSE | T3 RMSE | T3 \|H\|max | σ_min |
|---|---|---|---|---|---|
| `tseries` | 60 N·m·s（30%） | 1.547 | 19.38 | 63.7 | 7.25 |
| `tseries_h50` | **100 N·m·s（50%）** | 1.547 | **26.07（更差）** | **111.2** | 9.66 |

**把预算从 60 放宽到 100 让结果更差**：CMG 被允许堆更多动量、框架被推得更深，
|H| 冲到 111 N·m·s（已接近单轴硬件 107.7 与集群 200 的水平），误差反而更大。
所以满幅 T 组的失效**不是预算太小，是容量与近奇异**——调权重/预算解决不了。

## 5. 结论

1. **CMG 在 C 组任务上明显优于纯舵面（0.4449° vs 0.4706°）**，而且对气动模型
   20% 的失配不敏感。
2. **C 组的真正结论是"控制结构决定 CMG 能不能用"**：分层分配发散（92°，
   σ_min 4.12），统一 MPC 稳定（0.445°）。换成 CMG 之后这个结论依然成立。
3. **T 组满幅任务超出 CMG 硬件能力**（俯仰轴需求 116.5 > 单轴可用 107.7），
   表现出来是近奇异导致滚转权限丢失 + 137 步 QP 回退 + 姿态发散。
4. **可操作的调整**：三轴任务把逐轴需求压到 ≤ ~80 N·m·s，等价于
   ①幅度缩到 0.6 倍，或 ②机动时间拉长到 30 s。两种做法下 CMG 都稳定，
   并且把三轴 RMSE 降低 **50%（Tm=30 s）或 52%（0.6 幅度）**。
5. **放宽动量预算不是解**（60→100 反而 19.4°→26.1°）。要真正提升满幅能力，
   必须增大 CMG 角动量容量（h0 或单元数）或加 RCS 作为动量汇。

---

## 6. 局限（如实说明）

1. **CMG 的权重与动量预算（60 N·m·s、`r_cmg=0.05/0.5`）是在"俯仰主导"的
   A/B 主实验上调定的**；用到三轴任务上不是最优配置。但第 4 节的预算实验表明
   放宽预算不会改善，因此"容量/近奇异"的定性结论不受影响。
2. **C 组任务在任何执行机构下都跟不上参考**（需求 146 N·m 峰值），
   因此 C 组数字衡量的是"扰动吸收"，不能读成跟踪精度。
3. 单步求解 0.25–0.36 s，超过 0.2 s 控制周期，不满足实时（见实施报告 §11）。
4. 原 README 的 T 组数字（T1 22.78° / T3 1.92°）无法复现：当年那张表所用的
   机动幅值/扰动缩放没有记录在仓库里。本报告所有 T 组结论都基于本轮实测。
5. 原始 C0–C4（反作用轮版）的复现结果见 `legacy/results/`：
   C0 0.456° / C1 10.41° / C2 24.82° / C3 0.331° / C4 5.23°，
   与旧 README 的 0.446 / 10.55 / 25.9 / 0.325 / 4.51 相差 ≤16%。
