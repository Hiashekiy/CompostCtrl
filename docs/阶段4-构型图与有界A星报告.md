## 3. 设计要点与取舍（全部写在代码文档串里）

1. **图是隐式的**：只按需生成邻居，因此 4 维网格不会爆炸；节点键是整数索引元组，
   局部半径 60°、行程 ±90° 双重夹紧。
2. **时间展开**：状态 `(v_i, j)`，边 `(v_i,j) → (v_l,j+1)`，同一构型在不同时间片代价不同（§5.3）。
3. **两级评估**（为了同时满足"约束下的可实现性"与 60 ms 预算）：
   * 筛选层用执行器约束的**支撑函数**
     `μ(γ,τ̂) = Σ_i |A_i·τ̂| γ̇_max + Σ_j |B_j·τ̂| δ_max_j`，
     缺口 `gap = max(0, |τ_res| − μ)`，其中 `τ_res = τ_req − M_aero0`。
     两项可分离，所以 μ 是该方向的精确上界；但它不保证 τ_res 可加实际可达（非各向同性），
     因此**只用于筛选与代价**。
   * 验证层对 A\* 最终路径的每条边用**与 plant 同一套模型的分配 QP** 重新求解；
     任一条边复核失败，整条路径作废（`status=unverified_path`），不下发（§7.3）。
4. **σ_min 只进 `J_sing`**。能力不足一律由执行器约束评估给出，不用静态奇异值替代（§5.4 的告诫）。
5. **启发函数取 0**（等价于有界 Dijkstra）：因为 `h` 不是剩余代价的可采纳下界，
   **本实现不宣称 A\* 的全局最优性**，目标是"有界时间内找到可行路径"（§7.1）。
6. **未来需求复用**：整链重算实测 40–56 ms，因此按 `demand_refresh_s = 1.0 s` 复用并前移窗口
   （条件：只剩 ≥10 片、姿态漂移 < 0.5°）。复用是工程选择，敏感性在阶段 7 一并测。

## 4. 实测性能（阶段 5 之前必须先看清的账）

| 项 | 实测 | 说明 |
|---|---|---|
| 单次节点展开 | ≈ 1.0 ms | 9 邻居 × 支撑函数筛选（含节点能力缓存的均摊） |
| 到达 60 层的最小成本 | ≈ 60 ms | 恰好吃满 `max_search_time_ms`；带绕行的路径会 timeout |
| 未来需求整链（n=60，2 子步） | 40–56 ms | 复用后摊薄到 ≈ 0 |
| 路径精确复核（60 条边） | 10.2 ms | 只在找到路径时发生 |
| 控制分配（单次 QP） | 0.19 ms 均值 | 与阶段 3 一致 |

**结论**：在 200 ms 控制周期下，"图搜索 60 ms + 复核 ≤ 10 ms + 分配 0.2 ms" 成立，
但**只有不走绕行**时成立。阶段 5/7 必须先解决这一点（减小层数、降低邻居数或缩短窗口），
否则 timeout 会成为常态，C 组退化成 B 组。

## 5. 本阶段得到的一个重要负面观察（如实记录）

在当前主场景（100 km、3°/20 s 俯仰机动）下，A\* 找到的最优路径是**全程保持原构型**：
代价 0.000、`|γ̇_ref|max = 0`。原因是未来需求峰值只有 **10.1 N·m**，而 CMG 保证力矩
**61.2 N·m**、气动另加约 11 N·m——构型如何摆放对本场景根本没有影响。

因此：

* 阶段 5 的"接入分配器的单场景闭环"在 3° 机动下 C 组必然与 B 组几乎无差别；
* **要让搜索有意义，主场景必须落在能力边界附近**（更大的机动幅度/更短过渡时间），
  这正是 §4.2 可行性扫描的任务；
* 这条观察会写进最终报告，不会为了"出正结果"去改硬件参数。
