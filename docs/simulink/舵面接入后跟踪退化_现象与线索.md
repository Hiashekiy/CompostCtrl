# 舵面接入后跟踪退化：现象、证据与排查线索

本文件是一次交接记录，供另开会话继续修复。所有数字均来自仓库内已保存的 60 秒飞行日志与模型参数，未做推测性填充；
标注"待确认"的是尚未验证的推断。

## 1. 现象

工程飞行闭环（`models/NearSpace_CMG_FlightControl*.slx`，含真实舵机、气动舵面、公开升阻替代模型、平动）里，
姿态跟踪明显差于无执行机构的 P0 姿态验证模型，而且**A/B 两组的差距方向也反了**：

| 场景 | 接口 | 组 | 最大姿态误差 | RMS |
|---|---|---|---:|---:|
| 工程飞行 60 s | 真实舵机 + 气动舵面 + 平动 | 仅舵面 A | **15.32°** | **6.25°** |
| 工程飞行 60 s | 同上 | 舵面+CMG B | **2.45°** | **1.18°** |
| P0 姿态验证 60 s（S00） | 总气动力矩直接进刚体，无舵机 | 仅舵面 A | 6.23° | 3.31° |
| P0 姿态验证 60 s（S00） | 同上 | 舵面+CMG B | 3.96° | 0.46° |

证据：`simulink/results/native_closedloop/tracking_report.json`、`p0_matrix_summary.csv`、
`B_surrogate_flight_60s.mat`、`P0_S00_pitch30_AB.png`。注意两者工况/接口不同，只能说明"接入真实舵面后表现变了"，
不能直接相减当作误差来源。

## 2. 直接量化：舵面顶死，力矩兑不出来

从 B 组 60 秒日志里取三个量（控制器命令 `commands(:,1:3)`、实际气动总力矩
`native_subsystem_log_0001`、舵面实际偏角/偏角速率 `native_subsystem_log_0003` / `0002`）：

| 指标 | B（舵面+CMG） | A（仅舵面） |
|---|---:|---:|
| 指令气动力矩 RMS（x/y/z，N·m） | 2.28 / **15.79** / 2.17 | 2.47 / **16.76** / 1.92 |
| 指令峰值（y，N·m） | **41.26** | **45.58** |
| 实际气动总力矩峰值（y，N·m） | **12.44** | 23.62 |
| 指令与实际的差 RMS（y，N·m） | **12.72** | 13.53 |
| 偏角峰值（度） | 25 / 20 / 20（正好等于限幅） | 25 / 20 / 20 |
| **停在偏角限幅上的时间占比** | 49.9% / **61.5%** / 63.3% | 45.6% / **80.5%** / 57.5% |
| 偏角速率达限时间占比 | 1.4% / 10.3% / 3.5% | 2.0% / 3.4% / 5.4% |

执行机构限幅（`data/vehicle_params.m`）：偏角上限 **25°/20°/20°**，偏角速率上限 **60°/s**。

**结论性描述**：俯仰通道控制器平均要 16 N·m、峰值要 41 N·m，而舵面长时间（60%–80% 时间）顶在 20° 行程端点上，
实际只能给出约 12 N·m（B 组），也就是**指令的 1/3**；速率限幅只在 3%–10% 时间起作用，属次要因素。

## 3. 头号嫌疑：控制器相信的气动能力包络与实际舵面严重不匹配

控制器按模型工作区里内嵌的"能力包络"（`native_reference_bank` 的 `tau_min`/`tau_max`）规划力矩。实测这个包络在飞行场景下是：

```
俯仰轴（第 2 行）下限范围：-1480.8  …  -8.42 N·m
俯仰轴上限范围：          -11.25   …  +1260.41 N·m
名义需求 tau_nom 跨度：   -64.6    …  +65.1 N·m
```

即控制器在某些时刻认为俯仰可以打到 **上千 N·m**，上限甚至出现负值（自相矛盾的包络）；
真实舵面在同样飞行条件下最多约 **12–24 N·m**。相比之下，P0 的 S00 工况包络是 ±34/±40 N·m，量级是合理的。

这解释了为什么"接入真实舵面后变差"：MPC 按虚高的权限去规划，分配器随后被偏角限幅顶死，实际力矩只兑现三分之一，
而 MPC 在下一拍基于新状态继续提出同样不可行的要求——跟踪自然退化。CMG 的存在只掩盖了一部分（B 组比 A 组好），
但它补偿的是框架速率通道，不改变气动通道被顶死的事实。

**待确认**：这个包络是怎么算出来的、为什么在 S08 A4 下降场景下量级失控。检查点：
- `simulink/py/export_online_plan_bank.py`（挑选 `plan['box']['tau_min'/'tau_max']`）
- `nearspace/torque_gap_authority.py` 的 `build_boxes` / `calibrate_scale`（舵面效能矩阵、动压标定）
- 场景配置 `configs/torque_gap_s08/cases/A4_descent_replay_S00_with_cmg.yaml` 及其 resolved 版本
- 该场景下 q̄ 只有 0.55–18 Pa，舵面效能随 q̄ 线性下降，若标定用了别的动压或把 CMG 权限算进气动盒，就会出现这种量级

## 4. 次要嫌疑

1. **分配器退化**：`hpipm/bounded_control_allocation.m` 是活动集枚举的有界最小二乘，输入是"总力矩 − 自然力矩"。
   当目标远超可行域时它只会把所有偏角推到边界，三轴之间没有优先级——可能出现"某个轴吃掉全部行程"。
2. **舵机动态滞后**：舵机是一阶环节（`modelgen/build_actuators_aero.m`），时间常数与控制周期 0.2 s 同量级时，
   即使不饱和也会带来相位滞后；目前只在 3%–10% 时间撞速率限幅，说明滞后是次要项。
3. **预测模型与真值的力矩定义差异**：MPC 预测里 `tau_a` 是"总气动力矩"，真值里它由舵面经气动导数产生（自然项 + 增量项），
   两者在攻角较大时不完全等价（线性导数 + 公开升阻替代）。

## 6. 复现与再测量

```matlab
cd('D:\项目\飞轮'); addpath('simulink'); init_paths;

% 1) 打开并跑 60 秒（B 组；A 组换 _SurfaceOnly）
open_system('simulink/models/NearSpace_CMG_FlightControl.slx');

% 2) 用已有日志出 A/B 对比图（不重跑仿真）
plot_flight_ab;

% 3) 重新生成指标 JSON
report_closedloop;
```

日志字段（飞行模型）：`states = [Euler(3) omega(3) gamma(4)]`、`commands = [tau_a(3) nu_cmd(4)]`、
`flight_conditions = [qbar V alpha beta]`、`reference_log_att_deg`（参考姿态，度）；
子系统日志编号不稳定，按父块判断：
- `Aerodynamic_Surface/Aerodynamic_Model` → 实际气动总力矩（3）
- `Aerodynamic_Surface/Surface_Actuator` → 偏角速率(3) 与 实际偏角(3)
- `Environment_And_Forces/Public_surrogate` → 机体系气动力（3）
- `Native_Plant/CMG/Drive` → 框架速率(4)、框架角(4)、加速度诊断(4)

测量力矩兑付情况的最小脚本（已验证可用）：读 `commands(:,1:3)` 与 `Aerodynamic_Model` 的那条日志，
两者逐点相减即"指令 − 实际"；偏角日志对上 `delta_max` 即可算饱和占比。

## 7. 已排除 / 注意事项

- **与 P0 的数字不能混比**：P0 是"总气动力矩直接进刚体"，没有舵机、没有气动导数、没有平动。
- **模型是生成物**：任何改动都要改 `modelgen/` 下的构建器再重建，GUI 手改会丢；重建时舵面/气动参数来自 `data/` 与 `build_actuators_aero`。
- **参考通路已改为信号线**（控制器第 2 端口 + `Reference_Manager`），与本题无关但排查时要知道：控制器不再读工作区的参考库。
- **已排除**：CMG 反作用力矩缺失（`verify/check_actuation` 通过）、参考接入错误（与改造前逐位一致）、
  P0 十六组指标（与基线 0.00% 差异）。

## 8. 建议的下一步（按性价比排序）

1. 把飞行场景的 `tau_min/tau_max` 包络与"同 q̄ 下舵面实际可达力矩"画在一张图上，确认量级错在哪一步标定；
   若确认包络误算，先修 `torque_gap_authority`/导出脚本，再重导参考库并重建模型（这一步可能就解决大部分问题）。
2. 若包络无误而确实"能力不足"，则问题转为控制策略：让 MPC 在能力受限时优先保姿态、牺牲其他轴，
   或加"未达指令"的反馈（分配残差回灌），而不是继续要求不可行力矩。
3. 再评估舵机时间常数与控制周期的匹配（可做 0.1/0.2 s 控制周期对比）。
