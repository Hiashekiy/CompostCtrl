# 力矩约束收缩与 20 ms 力矩闭环：双方法 A/B 消融实验报告

> 分支：`experiment/torque-margin-feedback-ablation`（起点 `experiment/fast-torque-authority` @ `27f180d`）
> 认证模式固定 `analytic_full`；上层力矩级 MPC、控制周期 0.2 s、最多 4 轮 SQP、物理步长 1 ms 全部未改；参考轨迹 / MPC 权重 / 气动参数 / CMG 配置 / 无恒定外加扰动力矩 全部未改；生产默认仍是 `shrink=0` + 旧 0.2 s 分配器。
> 所有数字来自本轮 8 组 60 s 闭环仿真（301 个上层拍、60001 个 1 ms 采样），由脚本从 `summary.json` / 闭环 MAT 生成，没有手抄。

## 0. 一句话结论

- **方法 M（10 % 力矩盒收缩）**：把三轴**绝对**力矩误差的合成 RMS 降低 14.5 %（A）/26.8 %（B），A 组副翼偏角饱和从 81.9 % 直接归零；但**姿态跟踪没有任何改善**（A 3.825°→3.863°，B 1.110°→1.102°）。
- **方法 F（20 ms 实际舵偏反馈 + 一步预测）**：**力矩跟踪变差**（合成误差 +17.9 % A / +16.3 % B），B 组姿态 RMS 明显改善（1.110°→0.663°）、A 组不变（3.825°→3.870°）；下层每拍 0.44–0.52 ms 均值、最大 30.6 ms（只出现在第一个拍，MATLAB 首次调用开销）。
- **组合 MF10**：A 组合成力矩误差 0.5325 N·m（优于 B0 与 F20、与 M10 相当）；B 组比两个单独方法都差（合成 0.4069、姿态 1.557°）。**交互项为害**（B 组姿态交互 +0.902°）。
- **不建议切换生产默认**。见第 10 节。

## 1. 背景与控制结构

上一轮（`docs/simulink/19_torque_tracking_fast_certificate.md`）确认：`analytic_full` 与 `legacy` 逐位等价，力矩跟踪相对误差约 10–15 %，来源是**舵面偏角饱和（A 组滚转 81.9 %）与速率限幅造成的响应滞后**，不是求解精度。本轮在此基础上只考察两种改法：

```
              姿态/角速度/CMG反馈 (1 ms)
                        |
                原力矩级 MPC  (0.2 s, SQP<=4, 认证力矩盒)
                 |                          |
           tau_cmd 三轴                nu_cmd(4)  → CMG（B 组原样）
                 |
              ZOH 0.2 s
                 |
   M 组：力矩盒在 MPC 内部按 c±(1-α)h 收缩（QP 界、outside 检查、restore、首控校验同一套）
   F 组：20 ms 力矩闭环 + 一步舵机预测 → delta_cmd   <-- delta_actual(实测)、qbar/V/α/β、omega
                 |
         真实舵机（1 ms，delta_max/delta_dot_max/tau_s 未改） → tau_actual → 飞行器
```

| 代号 | MPC 力矩盒收缩 α | 下层 | 下层周期 |
|---|---|---|---|
| **B0** | 0 % | 原 `native_surface_allocation_sfun` | 0.2 s |
| **M10** | 10 % | 原 `native_surface_allocation_sfun` | 0.2 s |
| **F20** | 0 % | 新 `native_torque_feedback_allocation_sfun` | 0.02 s |
| **MF10** | 10 % | 新 `native_torque_feedback_allocation_sfun` | 0.02 s |

A（仅舵面）/B（舵面+CMG）各一组，共 8 组 60 s。

## 2. 方法 M：力矩盒收缩的实际生效位置

新增纯函数 `simulink/hpipm/online_shrink_certified_torque_box.m`：

```
c_k = (tau_max_raw + tau_min_raw)/2 ,  h_k = (tau_max_raw - tau_min_raw)/2
tau_min_mpc = c_k - (1-alpha) h_k ,   tau_max_mpc = c_k + (1-alpha) h_k
```

- 统一相对收缩，中心不动，零宽轴保持零宽，**不扩盒**；`alpha=0` 走**比特级直通**分支（不做任何算术），因此生产配置不可能因舍入漂移。
- 非法输入（`alpha<0`、`alpha>=1`、NaN、端点错序、非有限值）一律 `error`，不会静默放宽。

生效位置（`simulink/hpipm/online_authority_rollout.m`）：

1. 每个预测阶段在**原始盒 + 证书完成之后**、`outside` 检查之前计算收缩盒；
2. `outside` 判定、`restore` 裁剪、`authority.tau_min/max`（→ `native_online_rti_step.m` 里 `work.tau_min=a.tau_min` 送进 QP 的硬界）以及 `online_verify_first_command`、`verify_authority_candidate` 全部使用**收缩盒**；
3. 原始盒另存 `authority.tau_min_raw/tau_max_raw`，并记录 `authority.shrink_ratio`、`authority.shrink_abs_Nm`、`authority.restored`（该阶段是否发生恢复裁剪）；
4. 八顶点/单调区间证书仍然只证明**原始盒**；收缩盒是其子集，因此证书成立，但报告里不把原顶点数值当成收缩后的顶点；
5. `tau_nat`、`B_delta`、CMG 的 `gdot/gddot`、预测动力学、代价、权重、SQP 接受策略、`delta_max`/`delta_dot_max` 全部未改。

## 3. 方法 F：20 ms 力矩闭环与真实反馈接线

新增文件：

| 文件 | 作用 |
|---|---|
| `simulink/hpipm/online_servo_endpoint.m` | 现有 1 ms 舵机递推的闭式 20 ms 末端预测 `F_dt(δ_actual,u)`，同时给出每轴斜率 `1-κ` |
| `simulink/hpipm/online_torque_feedback_step.m` | 3 变量有界阻尼 Gauss-Newton（≤4 次内迭代），含受限静态分配回退 |
| `simulink/hpipm/native_torque_feedback_allocation_sfun.m` | `SampleTimes=[0.02 0]` 的 S-function，逐拍记录诊断 |

控制律（与方案一致）：

```
u* = argmin_{u∈U_k} || tau_cmd - tau_nat - B F_20ms(δ_actual,u) ||_{W_tau}^2 + λ || D_δ^-1 (u-u_prev) ||^2
U_k = [-δ_max, δ_max] ∩ [u_prev - δ̇_max·0.02 , u_prev + δ̇_max·0.02]
```

- `tau_nat`、`B` 由 `online_aero_moment` 用**同时刻实测** `air=[q̄,V,α,β]`、实测 `omega`、实测 `δ_actual` 计算；不使用未来参考、不使用评价用输出。
- `W_tau = I`（明确说明：没有按轴归一化，也没有用任何测试输出调参）；`λ=1e-3`；`dt=0.02`；最多 4 次内迭代；`D_δ=diag(δ_max)`。
- 初值 = `bounded_control_allocation(B, tau_cmd-tau_nat, lo, hi)`（前馈静态分配），每次迭代带投影与 4 步回溯，**要求代价单调不增**，否则退回初值并记 `fallback`。
- 病态 `B`（`rcond<=1e-10`）、非有限值、越界、代价上升 → 一律进入**受限静态分配安全回退**并计数、记录时刻。

Simulink 接线（`simulink/modelgen/build_closedloop.m`，新增第 10/11 个可选入参 `torque_shrink_ratio`、`torque_inner_mode`，前 9 个入参语义未变）：

1. 保留 `native_surface_allocation_sfun` 与 `Allocation_inputs`（B0/M10 用），F 组改为新建的 `Torque_feedback_allocation` 块；
2. 新块输入：`tau_cmd`(控制分量) / `Aerodynamic_Surface/1`（**实测** `delta_actual` 输出）/ `Environment_And_Forces/2`（实测 `air`）/ `Native_Plant/6`（`omega`）；输出 `delta_cmd` → `Aerodynamic_Surface` 输入；
3. `Previous_Allocation_Command` 在 F 组改为 **0.02 s 的 UnitDelay**，把「t⁻ 时刻实际已经施加的下层指令」送回上层预测器（B0/M10 仍为 0.2 s）；
4. 新增 `delta_cmd` 的 ToWorkspace 记录（两个组都有）；
5. 没有引入代数环：`Aerodynamic_Surface` 的 `delta_actual` 是舵机 `UnitDelay` 状态输出，对 `delta_command` 无直通；`omega`/`air` 来自飞行器状态与大气模型，无直通；上层 MPC 在 0.2 s 采样，天然切断回路。首次冒烟即通过，未出现 `代数环` 报错或「多一拍延迟」。

**必须声明的边界**：20 ms 内多次改写舵机指令会改变旧 `online_authority_rollout` 在整段采用常值命令的预测执行轨迹，因此旧的「阶段末端可达性证书」**不认证**新的 20 ms 闭环执行路径。本轮的安全主张限于**实际仿真验证**（见第 4 节断言与第 7 节饱和统计），不宣称「所有中间时刻力矩可行」。

5. 真实舵机的 `delta_max`/`delta_dot_max`/`tau_s` 全程未改；上面「指令速率饱和」是**下层指令**的限幅，不是物理速率限幅，二者分开统计。

## 9. 失败与异常

**本轮没有失败组**：8 组 60 s 全部完成（`failures.json` 为空），无 NaN、无物理越界、无上层回退、无下层回退、无证书失败（`all_certified=true`，全部 `analytic_box` 阶段）。

需要如实记录的**限制**：

1. **F 组把两件事捆在一起**：方案 §3.4.5 要求上层预测器拿到「t⁻ 时刻实际施加的指令」，所以 F20/MF10 里 `Previous_Allocation_Command` 从 0.2 s 缓存改成了 0.02 s 缓存。这会改变 MPC 每阶段的 `previous ± δ̇_max·0.2 s` 可达区间，从而改变 QP 可行域与指令。**因此本轮无法把「20 ms 反馈律」的贡献与「上一拍指令语义修正」的贡献分开**；表 8 中 F20 的耗时/QP 次数变化也部分来自这里。要分离需要再做一组「20 ms 反馈 + 保留旧 0.2 s previous」的对照，本轮按方案未做（方案只允许加做 M05/MF05）。
2. **旧末端可达性证书不覆盖 20 ms 闭环执行路径**（第 3 节边界），安全主张只来自实际仿真里的限幅断言与统计。
3. 所有结果为**每臂单次 60 s**。踩坑记录 §6.5 指出单次运行不足以对耗时下结论（legacy-B 自身两次运行最大值就有 220/306 ms 的差异），本轮耗时结论同样只作参考；方案允许的 `M05/MF05` 敏感性组**已补跑**（见 5.3），但按方案它们不参与主结论判断。

### 10.2 逐条回答

1. **单独把认证力矩盒收缩 10 %，是否降低真实力矩误差？是否恶化姿态跟踪？**
   降低了**绝对**/合成力矩误差（A −14.5 %、B −26.8 %，俯仰轴 0–15 s 段 2.046→1.740、0.813→0.386 N·m），但**没有**降低逐轴**相对**误差（滚转/偏航变差，因为目标幅值同时变小）。姿态**没有明显恶化**（A +0.038°，B −0.008°，都在 1 % 量级以内）。副作用是 MPC 耗时上升约 10–15 ms、QP 次数上升，且 A 组 2 个拍超过 200 ms。结论：M10 在「绝对力矩跟踪 + 消除偏角饱和」上有真实收益，在「姿态跟踪」上收益为零。

2. **20 ms 实际舵偏反馈 + 一步预测，能否改善物理滞后造成的误差？额外计算是否合理？**
   在**力矩层面没有改善**：A 合成误差 +17.9 %、B +16.3 %，三个轴的绝对误差全部变大；A 组偏角饱和反而从 81.9 % 升到 85.3 %（over-drive 把舵面更早压到限幅）。在**姿态层面 B 组明显改善**（1.110°→0.663°，−40.3 %，峰值 3.62°→2.27°），A 组不变。额外计算**合理且有余量**：每 20 ms 0.44–0.52 ms 均值、P95 ≤1.0 ms、3001 拍里只有 1 拍超过 20 ms，且那 1 拍是首拍冷启动。结论：计算代价可接受，但「能改善滞后误差」在**本测试场景不成立**，只在 B 组姿态指标上出现无法用当前数据唯一归因的改善（见第 9 节限制 1）。

3. **组合方案是否优于两个单独方案，还是互相抵消？**
   分臂看：A 组合成力矩误差 B0 0.6012 → M10 0.5140 → MF10 0.5325，即 MF10 优于 B0 与 F20、略逊于 M10，姿态与两者持平（3.852° vs 3.863°/3.870°），偏角饱和同样归零 —— 组合在 A 组**没有额外收益，也没有额外损失**。B 组 MF10 的合成误差 0.4069、姿态 1.557°，**同时劣于 M10（0.2865/1.102°）与 F20（0.4549/0.663°）**，交互项 +0.902°（姿态）、+0.0568 N·m（合成误差）都为正。结论：**在 B 组两种方法互相抵消**（收缩压低了力矩需求，20 ms 反馈又按 20 ms 末端去 over-drive，两者对舵面工作点的作用方向相反），不能宣称协同。

4. **A 组已有严重偏角饱和、B 组存在速率饱和，性能改善是否受物理极限而非控制律限制？**
   是。A 组滚转副翼 81.9 %/85.3 % 的时间顶在 0.436 rad 的限幅，此时真实力矩等于 `B·δ_max`，任何控制律都无法再改变它；速率饱和在 B 组俯仰/偏航 10.9–14.2 %（B0）也说明 0.2 s 内可用偏角变化被 1.047 rad/s 卡住。M10 把偏角饱和清零后姿态仍无变化，进一步说明 A 组的剩余误差主要不是「要得太多」而是「无论如何都到不了」与该轴的真实力臂限制；B 组则是速率限幅主导。**因此 10 % 级别的控制律改进空间已经被物理极限封顶。**

5. **是否值得继续研究或切换生产默认？**
   **不切换生产默认**（生产仍是 `shrink=0` + 旧 0.2 s 分配器，未改）。值得继续研究的方向只有一个并且要带条件：M10 的「绝对力矩误差下降 + 偏角饱和归零」值得在**更多场景/重复运行**下复核，并检查它是否以牺牲机动快速性为代价（本轮 A 组 0–15 s 俯仰误差下降但姿态无改善，需要看姿态收敛时间的差异）；F20 在能分离「上一拍指令语义」之后才值得再评一次，否则它的效果无法归因。
