## 一、研究目的与结论边界

比较三种控制方案在不同**俯仰正弦参考幅值**和**频率**下的周期跟踪表现，判断联合 CMG 是否改善较快周期机动的响应，并从舵面、CMG 实际执行情况解释性能变化。

要回答：
1. 不同频率下，目标正弦幅值有多少被实际姿态跟随？滞后多少？跟踪 RMSE 多大？
2. 1°、3°、5° 幅值增大时，上述表现是否变化？
3. 仅舵面 MPC、传统 PID+CMG、联合 MPC 的差异来自何种执行限制或控制行为？
4. 旧实验在 0.10 Hz 不通过、0.15 Hz 却通过的现象，在新设置下是否重复？若出现，能否用实际飞行状态、稳态偏置、谐波、执行器饱和或数值异常解释？

**论文使用名称**：`不同幅值与频率下的周期性姿态跟踪性能`。目前的六自由度模型存在随时间变化的飞行状态，且 MPC 非线性、有预测参考，不能未经额外固定工作点验证就将它称作严格的 LTI 频率响应或宣称“带宽提高多少倍”。

## 二、三种对照方法（固定，不临时增加）

| 方法标识（建议） | 控制方式 | 执行机构 | 说明 |
|---|---|---|---|
| `SURFACE_MPC` | 现有 MPC（每周期最多 4 轮 SQP） | 仅舵面 | 仅舵面硬件基线，不是同硬件算法比较 |
| `PID_CHAIN_CMG` | 实验二重新整定的姿态 PID + **舵面优先→CMG 补足**链式分配 | 舵面+4 CMG | 传统控制算法基线；默认关闭反应式卸载，避免增加额外变量 |

**实验二是硬前置依赖**：只有在实验二的链式分配实现、单独标定、冻结 PID 参数和基本验收完成后，才能开展实验四的正式全量 PID 测试。不得使用旧代码中的固定 `0.7*target` 分配，也不得在实验四中对每个频率单独调 PID。应保存实验二的 `PID` 参数文件、分配器代码哈希、标定记录与卸载开关状态，并在全部 27 个 PID 工况中固定使用。若实验二尚未完成，允许先进行 MPC 两方法的预检，但必须标为 `PRECHECK`，不能将旧 PID 数据混入正式 81 组。

## 三、正式测试矩阵：3×9×3＝81 次

### 3.1 幅值与频率

- 正弦俯仰角幅值：`[1, 3, 5]` 度，幅值指相对初始目标俯仰角的**峰值**，不是峰峰值。
- 频率：`[0.02, 0.04, 0.06, 0.08, 0.10, 0.12, 0.15, 0.18, 0.20]` Hz。
- 控制方法：上表三种，共 `3×9×3=81` 个唯一正式配置。
- 滚转、偏航参考保持初始目标；所有组使用同一目标姿态叠加约定、同一四元数生成方法，并通过有限差分或解析导数生成一致的期望角速度。
- 正弦启动时间采用现有 `s.onset=8 s`，以兼容现有生成器。`θ_ref(t)=θ_0+A sin[2π f (t−8)]`（`t>=8`）；启动前等于初始目标。**启动处角速度可能从 0 跳变，不应将启动瞬态直接纳入稳态评估**。如改为平滑渐入包络，应在所有配置统一使用，并清楚记录包络及稳态有效周期数；不允许仅对表现差的配置单独修改。

### 3.2 仿真时间和分析窗口

默认复用现有 `s.duration = 8 + 4/f`，即启动后覆盖**完整 4 个正弦周期**；所有三种方法在同一 `(A,f)` 下严格使用相同的时间边界。

|---:|---:|---:|
| 0.02 | 200.000 | 208.000 |
| 0.04 | 100.000 | 108.000 |
| 0.06 | 66.667 | 74.667 |
| 0.08 | 50.000 | 58.000 |
| 0.10 | 40.000 | 48.000 |
| 0.12 | 33.333 | 41.333 |
| 0.15 | 26.667 | 34.667 |
| 0.18 | 22.222 | 30.222 |
| 0.20 | 20.000 | 28.000 |

记录的输出时间须与 Simulink 实际固定步长 `0.001 s` 一致：例如预定终点不是 1 ms 整数倍时，记录实际终点，并在拟合时使用**实际采样时间和正弦相位**，不能假设绝对齐整。**主要指标固定使用最后两个完整周期**；如果仿真未覆盖该窗口，判为无效/中断，不对不完整周期计算“稳态频率响应”。

重要限制：`8+4/f` 导致不同频率使用**不同长短的实际飞行时间**，高度/动压/迎角等可能明显不同。因此本实验首先是“时变飞行状态下按频率分类的周期跟踪测试”。不同频率间的曲线是经验比较，不构成同一冻结工作点的严格频响。必须执行第七节的飞行状态审计。不要为凑结果给各频率随意换高度/初态，也不要暗中固定平动状态以绕过物理模型；如另做固定状态补充，须作为清晰独立的验证工况标记，绝不混入 81 组主表。

### 3.3 运行前预检

先试跑 `A=[1,3,5]°`、`f=[0.02,0.10,0.20] Hz`，至少对 `SURFACE_MPC` 与 `JOINT_MPC_CMG` 进行试跑，确认：
- `reference_bank` 时域、正弦相位、参考角速度正确；
- Simulink 真实运行，执行器/气动模型有效域检查正常；
- 统计指标正确，不因 1° 指令过小误判；
- 长时长工况可正常保存日志，未无意截断 `reference_bank` 或插值扰动；
- 实验二冻结 PID 已通过时，追加 `PID_CHAIN_CMG` 的相同试跑。

预检失败只能用于定位问题；不得改变正式矩阵的幅值、频率、场景或评分阈值以迎合结果。必要的代码修复需注明提交及复测，预检输出与正式批次分目录。

## 四、评价指标：三个主指标 + 解释性指标

### 4.1 正弦幅值增益（dB 和原始幅值比）

在最后两个完整周期内，用**相同频率**的正弦、余弦加常数项及可选线性趋势项拟合实际俯仰角：

`θ(t) ≈ a sin(2πf(t−8)) + b cos(2πf(t−8)) + c + d(t−t̄)`。

实际基频幅值 `A_out=sqrt(a²+b²)`。参考也用相同窗口/基函数拟合得到 `A_ref`，或者在确认参考准确时使用给定 `A`：

- `gain_ratio = A_out/A_ref`
- `gain_db = 20 log10(gain_ratio)`

同时输出 `A_ref_deg`、`A_out_deg`、`gain_ratio`、`gain_db`。当参考幅值近零、数据不完整、拟合退化时返回 `NaN + 原因`，不能默默给 0 dB。拟合的是**基频分量**，不等于真实曲线没有偏置/失真。

### 4.2 相位滞后（度）

从相同正弦拟合参数计算 `φ_ref=atan2(b_ref,a_ref)` 与 `φ_out=atan2(b_out,a_out)`，计算带符号的相位差，并明确采用约定：

`phase_lag_deg = wrapTo180(φ_ref − φ_out)`，**正值表示实际响应相对参考滞后**。

避免把 `phase_out − phase_ref` 和“相位滞后”混用。若基频实际幅值过小、相位失去物理可解释性，则输出数值同时标注 `phase_unreliable`；相位包裹至 `[-180°,180°]`，并可补充基于相关性的延迟解释，但不可任意选择包裹值美化曲线。

### 4.3 轨迹跟踪 RMSE（度）

主指标对同一窗口内**参考俯仰角与实际俯仰角**直接计算：

`pitch_rmse_deg = sqrt(mean((θ_actual−θ_ref).^2))`。

同时保留三轴四元数姿态误差 `attitude_rmse_deg` 和 `peak_error_deg` 作为补充，以防其他轴明显失控却仅报告俯仰指标。统一插值时间基准；分别注明基频指标、俯仰误差、三轴姿态误差的口径。**不要再以“RMSE≤1°”作为对所有幅值统一的主合格标准**，因为在幅值 1° 时零响应也可能获得约 `0.707°` 的 RMSE。

### 4.4 必须记录的解释性指标

- 最后两个周期的实际高度、动压、速度、迎角范围与最大漂移比例；正式组初始状态和实际采样窗口；模型有效域越界的时间与信息。
- 三轴舵面**实际偏角/偏转速率**、饱和比例；实际舵面气动力矩与目标气动力矩、力矩跟踪残差。
- 4 个 CMG 的实际框架角、框架角速度/速率饱和比例、三轴真实 CMG 力矩、角动量；必要时记录框架角加速度或执行速率环误差。
- MPC 平均、P95、最大单周期求解耗时及超过 0.2 s 的比例；回退次数/比例。PID 记录计算时间（可取得则记录，不能将不同计时路径直接等同比较）、链式分配的力矩残差和限制激活；卸载必须为关闭。
- 基频拟合质量：去掉基频和直流/趋势后的残差 RMS、直流偏置、趋势量、二/三次谐波幅值（可按需要追加）。用于判断 `0.10 Hz` 异常是否由非正弦畸变或漂移导致。
- 最后两个周期之外的全程峰值和故障状态另报，不能用末段拟合掩盖早期严重偏差。

**执行力矩要来自真实 Simulink 日志**。若现有日志中 CMG 力矩只能从框架角差分估计，须注明是估算，检查和实际 CMG 执行模型输出是否一致；不能混作实测直接控制力矩。

## 五、通过/失败/无效分类——先固定规则再计算

本实验的主交付是各频率下**连续的三个指标曲线和有效性标记**，而不是强行将每个测试简化为单一“通过/不通过”。

- `VALID_COMPLETE`：仿真完整、模型有效域内、日志齐全、最后两周期可用；其增益/相位/RMSE 不论好坏均原样记录。
- `VALID_POOR_TRACKING`：完整且域内，但跟踪性能很差；保留全部指标，可作为 `VALID_COMPLETE` 的细分标签。
- `MODEL_DOMAIN_FAIL`：迎角或大气等模型数据域越界，记录实际时刻/变量/阈值；保留日志，但**不能**计入有效域内的跟踪排名。
- `CONTROLLER_FAIL`：控制计算异常或满足已冻结的回退异常标准，记录具体含义；不要把“回退偏多”错误地说成“Simulink 崩溃”。
- `INFRA_FAIL`：脚本、文件、工具链或日志问题；修复后重跑，不能归为算法失败。
- `INCOMPLETE`：未结束、缺少完整最后两个周期、数据异常。

如需要额外展示“可接受跟踪”阴影区，**先声明且固定**参考的复合判据，例如 `gain_db≥−3 dB`、`|phase_lag|≤45°`、`pitch_rmse≤0.5A`；但该判据只能作为次要的工程阈值展示，阈值来源和适用性要说明，不可以测试后再调。不可从非单调的离散通过点直接推出唯一带宽值。

## 七、飞行状态可比性与旧异常核查（不可省略）

### 7.1 同频率的三方法配对审计

对每个 `(幅值,频率)` 输出三种控制方式最后两周期的气动条件表：`h_min/max`、`qbar_min/max`、`alpha_min/max`、速度范围及日志时间范围。三方法可能因姿态–平动耦合而演化出不同真实飞行状态，这是物理结果，**不能暗中改为相同状态**；但应标注其差异，避免将气动条件差异全部算到控制律头上。

### 7.2 不同频率的时间窗差异

在总汇总表单独列出各频率的 `t_analysis_start/end`、各项飞行条件均值/极值及漂移。若状态漂移显著，则说明频率曲线是**不同飞行阶段下的响应集合**，不能作为严格固定工况频率响应或带宽估计。

如果这一问题严重妨碍结论，额外提出独立的“共同飞行条件/固定工作点”补充实验建议并单独交付技术论证（先验证模型物理及接口可行），不要直接替换主矩阵或在本次工程中偷偷修改正式物理模型。

### 7.3 专门调查原 0.10/0.15 Hz 不连续现象

至少对 `1°`、`0.10 Hz` 与 `0.15 Hz` 的三方法绘制**最后两周期完整原始俯仰参考/实际响应叠图**，同时显示：
- 基频拟合曲线和残差、直流偏差/趋势、倍频谐波；
- 实际高度/动压/迎角；
- 实际舵偏角、框架速度与饱和；
- 求解异常、回退时刻（如有）。

阐明“高频幅值增益看似尚好但 RMSE 较大”是否来自相位、偏置、非正弦、其他轴漂移或不同气动条件。若不能查明，诚实写为尚未解释的异常，不得删除该频点或平滑曲线。
