## 2. 实验核心问题和三组控制方法

**要回答的问题**：在同一真实舵面+CMG 飞行器下，合理的传统 PID、反应式 CMG 卸载与本文统一 MPC 有何差异？传统卸载是否真的恢复后续机动所需的控制权限，并且没有明显破坏当前姿态跟踪？

统一测试这三种：

1. `PID_surface_first`：同一姿态 PID，舵面优先分配，剩余控制力矩由 CMG 补足，不卸载。
2. `PID_surface_first_unload`：**与上项完全相同**的 PID 增益和链式分配，唯一新增反应式卸载模块。
3. `MPC`：原仓库的舵面+CMG 原生 MPC，**保持原样**，0.2 s、最多 4 轮 SQP、23.2 s 原预测时域、相同 F20 下层。

禁止把 `PID_surface_first` 在主实验中改成更弱的算法、禁止为 MPC 改动力学或仿真精度、禁止单独给某个方法更宽松的约束。比较的是**传统控制栈与本文联合 MPC 控制栈**，不能把全部差异只归因于“PID vs MPC 算法”。

## 3. 舵面优先的链式力矩分配：必须具体实现

### 3.1 PID 只生成期望总控制力矩

沿用现有代码的四元数误差约定（含四元数短弧符号处理）、`omega_ref` 和抗积分饱和状态；不要擅自改变坐标轴、量纲、符号：

`tau_ref = Kp .* e + Ki .* I - Kd .* (omega - omega_ref)`，单位 N·m。PID 仅消费**当前**姿态/角速度参考，不读取未来窗口中的未来目标。正确处理姿态误差符号与四元数正负等价；积分器以实际可交付总力矩反馈进行抗饱和。

### 3.2 第一级：尽量用舵面完成目标力矩

当前实际状态计算 `tau_nat,B=online_aero_moment(...)`。以实际舵偏、实际/上一舵面指令调用 `online_surface_reachability(...)`，取得安全的端点可达舵偏区间 `[delta_lo,delta_hi]`。注意此区间是 0.2 s 端点外包估计，使用中不能声称 20 ms F20 完全达到。

解决一个**有界三变量最小二乘问题**，而不是分别剪裁三轴目标力矩：

`delta_star = argmin_{delta_lo<=delta<=delta_hi} ||W_a*(tau_ref - tau_nat - B*delta)||_2^2 + lambda_delta*||delta-delta_nom||_2^2`。

- 使用 MATLAB 原生有界最小二乘或仓库已实现且经过验证的 `bounded_control_allocation`，先核实其返回值语义与输入维数；不可临时引入 Python/外部优化器；不得通过 `B\...` 后简单饱和替代有界优化。
- 必须让**滚转和偏航耦合**生效。保留同一组明确固定的 `W_a`、`lambda_delta`，并记载选择原因。
- `tau_a_request = tau_nat+B*delta_star`，其中 `tau_nat` 为当前自然气动力矩，所有分配残差须保持“**总气动力矩**与**CMG 力矩**相加”的同一口径。`tau_a_request` 仍然是上层给 F20 的目标，不等于当前实际气动力矩。
- 当舵面能满足目标总控制力矩至数值容差时，**CMG 控制补偿应趋近于 0**（但卸载开启时允许有补偿性 CMG 运动）。
- 使用 `previous_command`、实际 `delta`、F20 预测检查指令可实现性；不能只拿理论目标判定“舵面已满足”。如端点估计导致 20 ms 跟踪差，记录实际残差，必要时改进参考可达估计；不能改物理舵机。

### 3.3 第二级：剩余目标力矩交给 CMG

`tau_remain=tau_ref-tau_a_request`；根据真实 `gamma` 计算 `A(gamma)`，使 `tau_cmg_request=-A*nu` 尽量接近 `tau_remain`。

求解有界正则化问题：

`nu_base = argmin_{nu_lo<=nu<=nu_hi} ||W_c*(-A*nu - tau_remain)||_2^2 + lambda_nu*||nu||_2^2 + lambda_change*||nu-nu_prev||_2^2`。

- 原生 4 CMG：`nu` 为四个框架角速度；约束使用 `vehicle_params().cmg.gdot_max/gddot_max`、0.2 s 采样及**上一实际/已执行**速率的可观测信息；检查真正的 CMG 驱动状态/输入是否足以取得“实际上一速率”，缺失时**如实记录使用的是上一命令的近似**，而不是声称真值。
- 不能把无约束伪逆结果逐元素限幅后称为最优；使用有界二次规划、穷举主动集或合理稳定的 4 变量求解器。若条件数不佳，输出有限安全命令并记录求解退化。
- 残差 `r_total=tau_ref - (tau_a_request-A*nu_base)`，计算并记录每轴三种力矩：`tau_ref, tau_a_request, tau_cmg_request`，还须从真值/日志获得 `tau_a_actual, tau_cmg_actual`。
- 该顺序是**优先级规则**，不是保证每个时刻实际力矩完美跟踪。若舵面权限、F20 滞后、CMG 饱和导致残差，必须暴露而非隐藏。

### 3.4 零力矩和边界测试

添加独立 MATLAB 单元测试（不能替代全模型仿真）：

- 舵面完全可覆盖目标时，`||nu_base||` 接近 0；
- 舵面不足时，CMG 输出方向必须缩小剩余误差；
- 滚转/偏航耦合下，实际 `B*delta_star` 确实位于真实可达集合；
- 舵面/CMG 饱和和接近奇异构型时，命令有限且不越约束；
- CMG 与舵面分配符号一致，`tau_a_request + tau_cmg_request` 等于上层预测总输出；
- 指令零与自然气动力矩不为零时，目标、自然力矩和 CMG 补偿不能重复计算；
- 同一输入序列输出可复现、没有代数环或采样时钟漂移。

## 4. 传统 CMG 卸载：必须有真正的物理效果和后续控制价值

### 4.1 定义：传统、反应式、非预知未来

保留滞回触发的**传统反应式卸载**，不允许读取未来参考，也不允许把本文 MPC 的未来预测机制移植到 PID。原 `H_on=80,H_off=60 N·m·s` 作为首选配置，仅在独立校准任务中必要时调整、报告依据，禁止针对最终测试任务临时调参。

更重要的是：**`||H||` 下降不等价于 CMG 任意方向力矩权限增加**。必须同时记录 `A(gamma)` 的各方向瞬时可控力矩、奇异性/条件数信息，并与后续实际姿态机动相对照。

### 4.2 卸载只能使用舵面剩余权限

已经得到姿态控制基线 `tau_a_request, nu_base` 后，构造卸载增量 `Delta_nu`：

`tau_cmg_extra = -A(gamma)*Delta_nu`

`tau_a_extra_request = +A(gamma)*Delta_nu`

故上层理想瞬时增加的净力矩为零。但实际执行中舵机有延迟，所以**不能仅用上式声称补偿真实成立**。在现有基础分配解的基础上考虑舵偏可达剩余集合、20 ms F20 能力和 CMG 框架速度/加速度限制，寻找能够让下一阶段角动量状态改善的 `Delta_nu`，并遵守：

1. **姿态控制优先**：只有基础姿态力矩残差足够小、舵面剩余力矩可覆盖 `tau_a_extra_request` 才允许卸载；否则 `Delta_nu=0`。
2. **舵面真实权限约束**：`tau_a_request+tau_a_extra_request` 必须存在真实可达舵偏对应，不能只落入一个逐轴剪裁的外接力矩盒就判定有效。可采用可达舵偏集合内的小规模求解/回代确认。
3. **CMG 速度、加速度约束**：最终 `nu_base+Delta_nu` 满足真实驱动限制。
4. **考虑舵机动态**：若舵面补偿相对 CMG 运动显著滞后，必须缩小卸载增量、暂缓动作，或定义有明确记录的渐进卸载速率限制；不得假设“指令补偿=实际补偿”。
5. **卸载作用方向**：预测一个短的**单步** CMG 构型变化（传统局部反馈允许，不调用未来任务），要求目标角动量或选定的构型恢复指标改善，并记录改善量；禁止仅靠 `H'*external<0` 就视为整个卸载成功。对物理定义核查 `dH/dt=A(gamma)*nu` 的符号。
6. **不以制造姿态误差换取卸载**：暂停/关闭卸载必须可对照，记录实际净附加力矩、姿态扰动和误差变化。

实现建议：以局部候选方向/有界优化产生 `Delta_nu`，按 `[1,.5,.25,.125,...]` 递减尝试且每次同时验证真值约束的可实现指令；该有限尝试是**卸载尺度控制**，不是修改本文 MPC 的四轮 SQP。使用固定参数/门槛；若无可行卸载步骤，就不卸载并写明原因（动压不足、舵面饱和、CMG 限幅、没有有利方向、实际补偿风险）。

### 4.3 关键验收：不是角动量下降就算完成

至少需要三类互补证据：

- **物理效果**：真实 `gamma(t)` 重建的 `H(t)` 的变化、真实舵面气动力矩和真实 CMG 力矩；对照“不卸载/允许卸载/低权限禁止卸载”；上层理想净零仅为辅助数据。
- **姿态代价**：卸载期姿态误差增量、峰值、舵面饱和、执行器限幅及实际附加净力矩，不能用 0 的代数补偿残差代替。
- **后续任务效益**：相同初态下先进行耗用 CMG 构型/动量的准备段，随后设置**完全相同的第二次机动**，比较是否恢复可用力矩、降低第二次机动 RMSE 或减少饱和。若卸载无收益甚至变差，客观记录，不得强行声明有效。

卸载法是可用于对照的传统策略，不是论文创新本身。若使用 `||H||` 控制不足以提高后续力矩权限，应如实说明**“角动量卸载”不一定等于“构型解奇异”**；不要在同一轮偷偷替换为复杂 MPC 奇异性优化，然后仍命名为传统卸载。

## 5. PID 重新整定：先冻结算法，再冻结参数，再正式测试

`simulink/paper/tune_pid.m` 的旧 4 个自然频率候选/两种角度校准不足以证明 PID 基线充分。新建**独立整定集**，不能拿最终论文测试工况既调参又报告无偏结果。

建议独立整定场景：5°/8°/12° 单次俯仰（过渡时间 4、8、12 s 中选具有代表性的组合）加一组小幅耦合机动；先检查飞行状态是否在模型有效域。使用有限且可复现的自然频率/阻尼比网格加局部细化，所有候选在同一组场景下评价，目标同时考虑 RMSE、峰值/超调、完成率、真实分配残差和执行器饱和，不允许因为某候选偶然获得更低 RMSE 就忽略不完整仿真。

整定策略：

- 先完成链式分配单元测试和短时/完整闭环，再整定 PID；**旧 70% 分配所选 PID 增益不能直接作为重构后最终参数**。
- PID 无卸载和有卸载**共享同一组 PID 增益**；卸载阈值/权重独立校准，参数冻结后再运行主测试。
- 如果调参使 PID 性能明显变好、MPC 优势缩小，保留真实数据；禁止刻意削弱 PID。
- 输出所有候选与失败原因、选择规则、最终固定参数和代码哈希；标明整定工况与最终评估工况不同。

## 6. 实验二正式场景（不重复实验一的大网格）

所有方法在相同物理模型、初始条件、参考、扰动、20 ms F20 内环、0.2 s 上层周期、1 ms 物理步长下运行，且使用实际飞行条件和相同模型越界保护。

### E2.1 典型单次机动：对比控制栈

- 俯仰增量 5°、10°、15°，参考过渡时间统一 5 s（可据有效域检查把 15° 放缓，但必须三种方法**同一版本**，记录调整原因）；机动开始时刻 8 s；60 s 总仿真。至少 3 场景 × 3 方法 = **9 次**。
- 输出同一坐标的姿态/角速率曲线、四元数最短旋转 RMSE 和峰值、过渡结束后及时稳定判据、真实舵面/CMG 力矩分担、分配残差、执行器饱和。
- 不可将中止的 RMSE 与完整运行 RMSE 直接排序。

### E2.2 连续机动：突出持续工作和卸载机会

- 设计两套**同一参考轨迹**的连续任务：一种正反向俯仰及滚转交替，一种同向多次机动使 CMG 持续消耗可用构型；实际过渡时间和幅值应根据模型有效域确定，保持三种方法完全一致。
- 特别记录每次机动分段 RMSE、前后 CMG 动量/构型/方向性力矩上界、舵面饱和、卸载开启时间及下一次机动表现。
- 至少 2 场景 × 3 方法 = **6 次**，若正常初始构型不触发卸载，**不能通过任意降低门槛造效果**；把它作为“不触发”的客观结果，转 E2.3 专用可重复场景验证。

### E2.3 卸载机理：单独验证“让行给舵面、恢复 CMG 后续控制能力”

- 采用两个有代表性且满足真实物理约束的**CMG 初始构型**：一个具有卸载空间、一个接近控制力矩权限受限的构型。明确记录真实 `gamma0,H0,A(gamma0)` 和有效控制权限，不能把同样 `||H||` 误认为同样奇异性。
- 至少设置一个“准备/卸载窗口 + 后续完全相同机动”场景，三种方法对照；此外对同一 PID 运行卸载开、卸载关、因舵面不足而自动暂停三组物理验证。
- 关键图：框架角与 `||H||`、实际舵面与 CMG 附加力矩、合成力矩、卸载开关、后续机动误差、CMG 分轴可用力矩变化。
- 这组可用于证明传统卸载行为及其局限，但如并无后续收益，应报告“卸载未在本场景提高后续任务性能”，**不能让验证脚本只因最终 H 下降就自动写 SUCCESS**。

## 9. 实施顺序和必须通过的验收门

1. **保护/预检**：记录分支、Git HEAD、原始正式 `.slx`/默认 bank SHA256；检查现有核心 MATLAB 函数及模型端口；建立新目录 `simulink/results/paper_experiments/E2_surface_first_v2/`，禁止覆盖旧批次。
2. **链式分配实现**：单元测试至少覆盖正常、饱和、耦合、零输出、自然气动力矩、CMG 近奇异、上一速率加速度限幅；先 2 s 冒烟，再 60 s 正常场景。无数值异常/越界。
3. **卸载物理实现和验证**：先证实真值驱动有响应，实际净附加力矩可测、卸载有无真实差异、低权限自动暂停；必须把 `H` 和可用控制力矩两者分别画出。若单项失败先修复，不允许只把验收状态写 true。

5. **运行正式实验二**：E2.1、E2.2、E2.3 所有配置均有真实 Simulink 原始输出或带堆栈的失败记录；未达模型有效域时按明确规则调整任务并对三种方法重跑同一场景，不选择性丢弃某方法失败。
6. **完整统计及图表**：自动生成 CSV/JSON、完整对照图 PDF/PNG、实际力矩/框架角/权限/卸载曲线；报告明确指出是否有改善、有没有触发卸载、效果有多大、有何代价。
