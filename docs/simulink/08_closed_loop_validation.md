## 修复：P0 B 组 CMG 框架驱动接线丢失（控制效果变差的根因）

### 现象

八组 P0 中 A 组（仅舵面）指标与历史 Python 的 `no_cmg` 臂几乎逐条吻合（S00 最大误差 6.228° 对 6.224°，RMS 3.315° 对 3.326°），
但 B 组（舵面+CMG）反而普遍劣于 A 组，且与 Python 的 `with_cmg` 臂相差数倍到数十倍
（如 S04 实际 0.0016°、修复前 18.26°；S02 实际 0.0043°、修复前 3.67°）。
A 组能对上、B 组对不上，说明被控对象、舵机、气动、参考与求解链路本身不是问题，问题在 CMG 通路。

### 证据链

1. **框架角恒为零。** 修复前 `B_attitude_60s_S00_pitch30.mat` 的 `states` 第 7–10 列（框架角反馈）在 60 s 内恒为 0，
   而同一时刻的框架速率命令已达到 ±1 rad/s 饱和。`max|gamma| = [0 0 0 0]`。
2. **第一控制步的角速度响应缺少 CMG 力矩。** 取 `J=diag(1200,8500,9000)`、`tau_d(0)=[0.1995 0.5 0.2995]`、
   `tau_a=-0.5678`，并用 Python 同一几何算得 `tau_CMG=-A(0)nu=(0.001,-1.0735,-0.0023) N·m`：
   - 无 CMG 时俯仰净力矩 −0.068 N·m，对应 Δω=−1.6e−6 rad/s——正是修复前模型的值（−0.004327 → −0.004329）；
   - 含 CMG 时净力矩 −1.141 N·m，对应 Δω=−2.69e−5 rad/s——正是 Python 记录值（−0.004327 → −0.004354）。
3. **单独驱动 CMG 子系统**（把 P0 模型里的 `Native_Plant/CMG` 拷到空模型，给常值 nu 命令）：
   `nu_actual=0`、`gamma=0`、`torque=0`，`A` 恒为 `A(gamma=0)`。即速率命令根本没有进入几何、角动量和力矩环节。
4. **连线检查**：在源模型 `CMG_Cluster`/`Plant_6DOF_CMG` 中 `nu_command→Drive`、`Drive→Split_1`(gamma)、`Drive→Split_2`(nu)、
   `Drive→{nu_actual,acceleration,gamma}` 都存在；在 P0 工况模型里这些线**全部消失**，只剩悬空的目的地线段。

### 根因

`build_closedloop` 的 `configure_ideal_p0_drive` 用 `Simulink.SubSystem.deleteContents`
把实测过的 P1 二阶框架驱动替换为理想速率执行加角积分。**deleteContents 会连同该子系统的
Inport/Outport 块一起删除，从而删掉父系统里挂在这些端口上的连线**，并在目的端口留下无源线段。
重建后的驱动块本身接线正确（孤立测试可正常积分），但它在 CMG 内部不再连到任何东西，
于是：`nu` 不入框架 → `gamma` 冻结 → `tau_CMG=-A(gamma)nu=0`、`H(gamma)≡H(0)=0`。
飞行器退化为纯刚体，而 MPC 仍在优化四个“并不存在”的框架速率，把气动舵面权限浪费在
无法产生任何物理效果的框架命令上，B 组因此比 A 组更差，且偏差随时间累积。

模型照常编译、仿真、零回退、数值有限，所以原先只检查“跑完+有限值+HPIPM 状态”的回归无法发现它。

### 修复

- `configure_ideal_p0_drive`：删除前记录该子系统全部端口的上下游连线，重建后**先清除悬空线段再重新连接**，
  并对每个端口断言 `get_param(port,'Line')>0`；速率限幅改由控制模板的 `gdot` 提供，不再硬编码 1。
- `build_closedloop`：P0 B 组构建后调用 `assert_connected`，逐个检查 CMG 子系统输入/输出端口均有连线，构建期即失败。
- 新增 `simulink/verify/check_actuation.m`：载入已保存的 P0 B 模型跑 2 s，断言框架角确实移动、框架速率命令确实到达 CMG，
  作为“惰性执行机构”的回归门（修复前该检查必然失败：`gamma_peak=[0 0 0 0]`）。
- `simulink/py/run_native_p0_matrix.py`：导出步骤加入锁竞争重试，避免 Windows 上 `.mat` 短暂占用导致的假失败。

### 残余差异（尚未验收）

- 真值积分：本模型 ode4/1 ms；Python P0 用 8 个 RK4 子步（h=25 ms）。
- 扰动力矩：本模型 `From Workspace` 零阶保持（控制周期采样）；Python 在子步中点查询连续扰动。
- 因此指标与 Python 同量级但非逐点等价；逐点轨迹等价、控制序列回放与步长收敛仍属未完成项。
  `check_actuation` 只锁住“执行机构是否真的动”这一类失效，不代替上述验收。

## 已通过的数值验证

- Aerospace 原生 6DOF 静止、匀速、恒力、恒力矩解析测试；最大状态误差 2.19e-13，积分四元数范数误差 2.30e-14。
- 库入口转发后的真实链接为 `aerolibprivatev1p5/6DoF (Quaternion)`，不是自建同名子系统。
- 原生 A/B 被控对象与独立 Python RK4 角动力学：最大角速度差分别为 5.90e-17、5.03e-17 rad/s，包含 -A*nu 与 -omega×H 两项。
- MATLAB 在线 QP 组装与 Python：Q 的最大差 2.91e-11，其余已读回矩阵/向量差为零，控制增量序列差 1.46e-13。
- 在线 RTI 首命令对照：B 组最大差 1.46e-11，A 组最大差 5.55e-17。移植保留了 Python 先预测初始轨迹、后裁剪初始命令的顺序；改变这个顺序会改变迭代结果。
- 热启动、有历史计划时回退、无历史计划时有界稳定器回退，均做了单独测试。
- 100 组舵面分配与 SciPy BVLS 对照：相对目标值差 4.41e-16，所有偏角均满足幅值与相邻控制周期速率界限。

## 八组 P0 的 A/B 对比图（与论文图同风格）

`verify/plot_p0_ab.m` 按论文侧 `figures/torque_gap_no_cmg_comparison/<phase>/<case>_AB.png` 的四面板风格，
为每组 P0 工况画一张 A（仅舵面，橙）对 B（舵面+CMG，蓝）的对比图：

| 面板 | 内容 |
|---|---|
| (a) | 该工况机动轴的姿态跟踪（参考虚线 / A / B），浅蓝底为参考机动区间 |
| (b) | 三轴短弧姿态误差范数，图例内含全程 RMSE 与峰值 |
| (c) | 该轴力矩分工：气动可行区间与上下限（绿）、参考需求 τ_nom、A/B 气动总力矩、B 的 CMG 力矩（青） |
| (d) | CMG 该轴角动量 H(γ) 与 ±4h₀ 参考（A 组无 CMG） |

机动轴按工况自动选择：`*roll*` → 滚转、`*yaw*` → 偏航、其余 → 俯仰。
生成：`plot_p0_ab`（全部 8 组）或 `plot_p0_ab('S00_pitch30')`（单组）。
输出：`results/native_closedloop/P0_<case>_AB.png` 与 `P0_<case>_metrics.csv`（最大/RMS/终值误差与该轴力矩峰值）。
