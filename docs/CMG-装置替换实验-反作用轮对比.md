# 装置替换实验：把 C 组 / T 组的反作用轮换成 CMG

**问题：** 原来的 C0–C4（俯仰任务）与 T1/T3（三轴任务）是用**反作用轮**做的。
把装置换成 **CMG** 之后效果如何？

**做法：** 保留两组任务的**原始场景与控制器结构**，只把"动量交换装置"变成一个
可切换的维度，在同一套环境/参考/初值/时间步下重跑。

```bash
python scripts/run_device_sweep.py --all --jobs 4     # 10 次运行，约 20 min
python scripts/plot_device_sweep.py                  # figures/cmg_ab/device_*.png
```

代码：`nearspace/arms.py`（装置臂定义）、`scripts/run_device_sweep.py`、
`configs/cmg_ab/device_sweep.yaml`。数据：`results/cmg_ab/device_sweep/`。

---

## 1. 场景与装置臂

| 组 | 场景 | 时长 |
|---|---|---|
| `cseries`（C0–C4） | 100 km 顶点，俯仰 **5° 余弦脉冲**机动 @105 s，持续 10 s | 200 s |
| `tseries`（T1–T3） | 100 km 顶点，**5° 俯仰 + 5° 滚转 + 3° 偏航**余弦脉冲 @110 s，持续 20 s | 150 s |

| 臂 | 装置 | 控制器 | 对应原算例 |
|---|---|---|---|
| `C1` / `T1` | 无 | 统一 MPC（仅舵面） | C1 / T1 |
| `C3_rw` / `T3_rw` | **反作用轮**：3 正交轮，60 N·m / 366.5 N·m·s/轴 / 12 kW，`\|M\|≤min(60, P_max·J_w/\|h\|)` | 统一 MPC（16 状态） | **原 C3 / T3** |
| `C3_cmg` / `T3_cmg` | **CMG**：4 单元金字塔，50 N·m·s/单元，γ̇≤1.5 rad/s，控制器力矩盒 61 N·m、动量预算 60 N·m·s | 统一 MPC（18 状态） | **把装置换成 CMG** |
| `C0_rw` / `C0_cmg` | 同上，但真值与控制器都用 10 ms 滞后（反作用轮标称 50/30 ms、CMG 标称 30 ms） | 统一 MPC | C0 性能上界 |
| `C2_cmg` | CMG | **分层**：力矩层 MPC + 伪逆操纵律分配 + 零运动 | C2 |
| `C4_cmg` | CMG | 统一 MPC，但**控制器气动系数偏 20%**（真值仍是标称） | C4 |

所有臂共享：NRLMSIS-2.0 大气、余弦跳跃弹道、参考姿态、初始配平状态、
`dt_ctrl = 0.2 s`、`dt_plant = 0.005 s`、同一套代价权重与评分容差。
**装置本身是模型的一部分**，所以不同装置臂的"真值模型"必然不同——这正是要比较的东西。

## 2. C 组结果（200 s，俯仰 5° 脉冲 @105 s）

| 臂 | 装置 | 三轴 RMSE [°] | 峰值 [°] | 俯仰 RMSE [°] | 装置峰值角动量 [N·m·s] | σ_min | QP 失败 | 平均求解 [ms] |
|---|---|---|---|---|---|---|---|---|
| `C0_rw` | 反作用轮（10 ms 滞后） | 41.77 | 179.6 | 13.06 | **634.8（3 轴全饱和）** | — | 0 | 353 |
| `C0_cmg` | CMG（10 ms 滞后） | **0.4446** | 2.63 | 0.445 | 11.76 | 37.97 | 0 | 246 |
| `C1` | 无 | 0.4832 | 3.32 | 0.483 | 0 | — | 0 | 75 |
| `C2_cmg` | CMG（分层分配） | **91.98** | 179.8 | 23.10 | 74.89 | **4.12** | 0 | 358 |
| `C3_rw` | 反作用轮 | 49.20 | 179.9 | 17.16 | **634.8（3 轴全饱和）** | — | 0 | 351 |
| `C3_cmg` | CMG（统一 MPC） | **0.4449** | 2.61 | 0.445 | 11.03 | 38.55 | 0 | 245 |
| `C4_cmg` | CMG（统一 + 失配 20%） | 0.4548 | 2.64 | 0.455 | 9.38 | 38.55 | 0 | 238 |

### 读数

1. **在这条任务上，CMG 完胜：0.445° vs 反作用轮 41.8°/49.2°（发散）。**
   机理可以直接从装置的力矩律读出来：
   反作用轮的可用力矩 `|M| ≤ min(60, P_max·J_w/|h|)` 随已存动量**衰减**——
   `|h|` 到 634 N·m·s 时只剩 `12000×0.7/634 = 13 N·m`，而 100 km 处气动权限仅约
   20 N·m，于是它连自己存下的动量都还不回去，姿态单调发散（图
   `figures/cmg_ab/device_cseries.png` 第 4、5 行：蓝色虚线在 150 s 后冲到 ±25° 限幅并持续振荡）。
   CMG 的力矩 `h0·γ̇` **不随储存动量衰减**（转子恒速），全程只用了 11 N·m·s。
2. **加上反作用轮反而比不加更差**（`C3_rw` 49.2° vs `C1` 0.48°）。这是装置本身的
   功率–力矩衰降造成的，不是"控制器用了不该用的装置"：一旦轮子被推上去就再也
   下不来。**这正是当年把反作用轮换成 CMG 的工程理由**
   （见 `docs/CMG-实现状态.md` §1：60 N·m @5000 rpm 需 31 kW）。
3. **控制结构仍然是决定性的（C 组原本要证明的事在 CMG 上依然成立）：**
   同一个 CMG，分层"力矩层 MPC + 伪逆分配"（`C2_cmg`）**发散到 92°**，
   而统一 MPC（`C3_cmg`）稳在 0.445°。原因是分层方案的规划层不知道
   `σ_min(A)` 与可交付力矩包线，把 CMG 推进了近奇异区
   （σ_min 掉到 **4.12**，远低于下限 12.25），指令力矩交付不出来。
4. **C0 上界只快 1.5%**（0.4446 vs 0.4449）：说明在这条任务上瓶颈不是执行机构滞后。
5. **C4 的 20% 气动失配几乎不痛**（0.4449 → 0.4548，+2.2%）。
   对比旧的反作用轮 C4（0.325° → 4.51°，+1287%）：CMG 提供的权限把气动模型误差吃掉了。

## 3. T 组结果（150 s，5° 俯仰 + 5° 滚转 + 3° 偏航脉冲 @110 s）

| 臂 | 装置 | 三轴 RMSE [°] | 峰值 [°] | 滚转/俯仰/偏航 RMSE [°] | 机动窗峰值 [°] | 舵面饱和比例 | 装置峰值角动量 [N·m·s] | σ_min | QP 失败 |
|---|---|---|---|---|---|---|---|---|---|
| `T1` | 无 | 1.230 | 4.43 | 0.634 / 0.512 / 0.926 | 4.43 | 25.6% | 0 | — | 0 |
| `T3_rw` | 反作用轮 | **0.2381** | **1.28** | 0.049 / 0.233 / 0.015 | 0.70 | 32.2% | **374.7** | — | 0 |
| `T3_cmg` | CMG | **19.38** | **88.16** | 18.39 / 4.00 / 4.82 | 18.29 | 27.2% | **63.69（超 60 预算）** | **7.25** | **137** |

### 读数

1. **在这条任务上结论反过来了：反作用轮赢（0.238° vs CMG 19.4°）。**
   三轴同时做 5°/5°/3° 的余弦机动，需要约 **375 N·m·s** 的储存角动量；
   反作用轮每轴 366.5 N·m·s、范数上限 634.7，可以全部吃掉；
   而 CMG 的**控制器动量预算只有 60 N·m·s**（集群硬件 200、单轴可用 107.7）。
2. **CMG 的失效链条**（图 `figures/cmg_ab/device_tseries.png`）：
   `|H|` 在 125 s 撞到 60 N·m·s 预算 → 径向包络禁止继续充电、且薄气段禁止卸载 →
   CMG 只能"冻结"动量，`σ_min` 从 38.5 掉到 **7.25**（低于 12.25 下限）→
   指令力矩 61 N·m 却交付不出（峰值记录 85 N·m，为近奇异放大）→
   137 步 QP 未正常收敛 → 误差从 125 s 起单调增长到 88°。
3. **T1 反而是三条里最好的"下限"**：无装置时舵面把误差压在 1.23°，
   说明 100 km 处 5° 级三轴机动本身没有超出手动权限；装置的加入必须
   "带来增益"，否则就是纯风险。

## 4. 两组放在一起：装置优势是任务相关的

| | C 组（5° 俯仰脉冲，200 s） | T 组（5°/5°/3° 三轴脉冲，150 s） |
|---|---|---|
| 需求角动量 | 小（CMG 实际用量 11 N·m·s） | 大（约 375 N·m·s） |
| **反作用轮** | **发散**（力矩随动量衰降，|h| 打满 634.8） | **最好**（0.238°，余量在 366.5/轴内） |
| **CMG** | **最好**（0.445°，预算只用 18%） | **发散**（预算 60 打穿，σ_min 7.25） |

**结论（可以直接写进论文）：**

1. **CMG 适合"单轴、持续、需要恒定大力矩"的场合**：力矩不随储存动量衰减，
   同一份角动量可以用得更久；在这类任务上它把反作用轮从"发散"救回 0.445°。
2. **反作用轮适合"三轴同时、总量大、短时"的场合**：它的角动量容量（366.5 N·m·s/轴）
   远大于这台 CMG 的控制器预算（60 N·m·s）与单轴可用量（107.7 N·m·s）。
3. **所以"把装置换成 CMG"不是一个单向的改进**，而是把失效模式从
   "力矩随动量衰减"换成"角动量容量不足 + 近奇异"。要两者兼得，必须
   **增大 CMG 角动量容量**或**加动量汇（RCS）**，而不是继续调权重。
4. **两组任务里，控制器结构的影响都不小于装置**：分层分配在 CMG 上直接发散
   （92°），统一 MPC 才是让 CMG 可用的前提。

## 5. 必须披露的局限（否则上面的结论会被过度解读）

1. **反作用轮臂的权重没有为新任务重新调参。** `mpc3` 的 `w_h = 5e-4` 很弱，
   意味着 MPC 倾向用轮子承担稳态力矩。如果做真正的动量管理（把 600 N·m·s
   卸给气动），在 100 km 只有 20 N·m 气动权限、需要 30 s 以上，**在这个任务时长内
   仍然来不及**——所以结论方向不会变，但发散的具体时刻会变。
2. **CMG 臂的动量预算（60 N·m·s）与权重是在"俯仰主导"的 A/B 主实验上定的**，
   对三轴任务是**劣化配置**。把预算放大到单轴硬件极限 107.7 N·m·s 会改善 T 组，
   但不会改变"容量不足"的定性结论（需求 375 N·m·s）。
3. **两组的控制周期都是 0.2 s，单步求解 0.25–0.63 s，不满足实时**（见实施报告 §11）。
4. **原 README 的 T 组数字（T1 22.78° / T3 1.92°）无法复现。** 用冻结配置重跑得到的是
   T1 1.20°/4.48°、T3 0.44°/1.97°（`legacy/results/`）。原因是当年那张表所用的
   机动幅值/扰动缩放没有记录在仓库里（`dist_scale_qinf`、`pitch/roll/yaw_amp_deg`
   在历史上被改过多次）。本报告的所有 T 组结论都基于**本轮实测**，不引用旧表。
5. **C 组在原代码里是俯仰通道单轴模型**；因为 CMG 的力矩必须靠 4 单元框架在三轴
   几何上合成，本轮把 C 组改到 6 自由度模型、用纯俯仰任务复现其研究目的
   （控制结构 / 分配 / 失配）。因此 C 组数字**不能**与旧 README 的 C0–C4 直接对比，
   只能在同一轮的 C0–C4 内部比较。
6. 原始 C/T 组的复现结果（`python legacy/run_all.py`）：
   C0 0.456° / C1 10.41° / C2 24.82° / C3 0.331° / C4 5.23°，
   与旧 README 的 0.446 / 10.55 / 25.9 / 0.325 / 4.51 相差 ≤16%（C4 最大），
   差异来自求解成功判据由 OSQP 状态字符串改为约束违反量（见核验文档 §7）。
