依据：`docs/CMG多场景姿态机动对照实验指导书_无CMG对照版.md`
代码与实现记录：`docs/torque_gap/no_cmg_vs_cmg_code_audit.md`

`reference_audit.md`、`P0/`、`P1/`、`smoke/`）；图：`figures/torque_gap_no_cmg_comparison/`。

## 1. 本轮要回答的问题

在**相同飞行器、相同基准惯量、相同气动舵面、相同任务条件**下，增加 CMG 并允许其参与控制，
能否改善不同姿态机动的执行效果？改善是否可重复、是否与机动前的构型迁移和角动量预置有关，
以及在真实舵面执行器（P1）下是否仍然存在。

## 2. 两组系统的实现口径

| | A 组（`cmg_present: false`） | B 组（`cmg_present: true, cmg_enabled: true`） |
|---|---|---|
| 状态 | `[q(4), ω(3)]` = 7 | `[q(4), ω(3), γ(4)]` = 11 |
| 控制 | `[τa(3)]` = 3 | `[τa(3), ν(4)]` = 7 |
| 平动姿态动力学 | `Jω̇ = τa + τd − ω×Jω` | `Jω̇ = τa − A(γ)ν + τd − ω×(Jω + H(γ))` |
| NLP（22 节点） | 227 变量 / 184 约束 | 407 变量 / 364 约束 |
| CMG 状态/诊断量 | **不存在**（CSV 中为空，标注“不适用”） | 全部记录 |

- A 组**不是**“把 ν 冻结为零”的模型：其 OCP 中没有 `γ`、`ν`、框架行程界、框架速率约束，
  动态方程中没有 `A(γ)ν` 与 `H(γ)`。单元测试 `test_5` 证明在非零角动量构型下，
  A 组动力学与“B 组令 ν≡0”给出不同结果（后者仍带 `ω×H`）。
- P1 两组走**同一段**舵面分配/限幅/伺服代码；A 组以 `cmg_on=False` 运行 18 状态真值，
  框架状态 `dx[10:18] ≡ 0` 且 `Hc = Mc = 0`。
- 惯量审计结论：现有 `J = diag(1200, 8500, 9000) kg·m²` 为**不含 CMG 的飞行器基准惯量**，
  两组共用。转子自转惯量可算出但极小（`diag(0.239, 0.239, 0.159) kg·m²`，
  ≤ 0.02%）；CMG 结构质量/安装几何在 `J` 中不存在，无法拆分。因此本轮是
  **匹配惯量的算法对照**，不是完整硬件移除后的质量级工程对比（见代码审查文档 §2）。

### 5.1 逐场景解读

**S00 基准俯仰。** A 组在 110–130 s 的俯仰指令被上界卡住：机动窗口三轴平均贴边比例 0.27，
`hi_y` 从 16.2 N·m（98 s）降到 7.7 N·m（110 s）、6.3 N·m（114 s），
而 30°/20 s 的五次多项式峰值需求约 60 N·m 量级，因此 A 的俯仰角误差累积到 6.0°。
B 组用 CMG 补齐缺口后 RMSE 0.096°、最大 0.20°，机动前角动量
`H = (−28.0, 155.8, 2.9) N·m·s`（|H| = 158.3），迁移提前 19.2 s。
**B 组舵面负担反而更高**（俯仰 RMS 10.42 vs 7.54 N·m）：A 组不是"省着用舵"，而是
被能力盒限制而无法产生完成机动所需的力矩；B 组真正执行了机动，因此舵面与 CMG 都在出力。

**S01 反向俯仰。** 除符号外与 S00 完全镜像：B 组机动起始角动量
`H = (25.3, −156.1, 3.5) N·m·s`，`Hy` 与 S00 反号（+155.8 → −156.1）。
**这是机制的强证据**：构型迁移方向由任务方向决定，而不是恒定朝某个方向漂移。
A 组 5.09°、B 组 0.152°。

**S02 小幅俯仰。** A 组本身已把误差控在 0.85° 以内（RMSE 0.553°）。B 组降到 0.007°，
相对改善虽大，但**绝对量级已在工程可接受范围内**：对 10° 的小幅任务，
"没有 CMG 就做不了"是不成立的，CMG 的收益主要是精度冗余而非可行性。
B 组此时几乎没有动用能力（σmin 最小 13.4，框架速率饱和 0）。

**S03 大幅俯仰。** A 组受能力限制最重：15.98° 峰值误差、10.99° RMSE。
B 组改善到 2.237°（−79.6%）但**没有消除**问题：能力盒贴边比例 0.97、框架速率饱和 12.4%、
σmin 最小 1e-4（近乎奇异）、|H| 峰值接近 200 N·m·s 上限、fallback 11.7%。
结论：45° 机动超出本构型"舵面 + 该 CMG"的联合能力边界，B 组只是把误差缩小到 1/5。

**S04 滚转。** CMG 辅助可推广到滚转轴：4.001° → 0.010°（−99.8%）。
此任务下所需 CMG 角动量很小（机动前 `H = (2.3, 4.8, 15.0)`，|H| = 16.0），
σmin 最小 19.2（远离奇异），框架速率饱和 0。滚转是本构型最"轻松"的 CMG 任务。

**S05 偏航。** A 组最差：20.58° 峰值误差、17.14° RMSE，且**机动前**误差就已达 10.6°，
说明在 90–110 s 的稀薄大气段偏航通道连参考姿态都跟不上。B 组改善到 3.205°（−81.3%），
但构型几何代价明显：机动前角动量 `H = (−28.4, 13.8, −59.8)`，σmin 最小 0.0000
（过程中穿越奇异），框架速率饱和 3.3%，机动窗口能力盒贴边比例 0.80。
**偏航方向 CMG 收益显著但能力受限**，属于本报告如实记录的能力边界。

**S06 同时多轴。** A 4.915°、B 0.098°（−98.0%）。B 组机动前角动量
`H = (−13.5, 157.2, −3.6)`，与单轴俯仰同量级，说明多轴任务中俯仰通道仍主导需求，
滚转分量由 aero+CMG 共同快速完成（滚转轴 |H| 贡献小）。两组贴边比例 0.63/0.70，
说明两个轴同时受到能力约束，不存在"把能力全部分给一个轴"的余地。

## 6. 阶段 2：S07 连续机动（90–180 s）

| 窗口 | A RMSE | B RMSE | A 最大误差 | B 最大误差 |
|---|---:|---:|---:|---:|
| 第一次机动 110–130 s（+30°） | 4.664° | 0.096° | 6.016° | 0.202° |
| 第二次机动 150–170 s（−30°，回基础姿态） | 0.387° | 0.040° | — | — |
| 两次机动并集 | 2.756° | 0.063° | 6.016° | 0.202° |
| 机动后 170–180 s | 0.003° | 0.000° | — | — |
| 机动前 98–110 s | 2.513° | 0.068° | — | — |

（两次机动的保持阶段 130–150 s 未并入任何单次机动窗口，符合指导书 §9.3。）

研究问题的回答：

1. **第一次机动结束后 B 组留下什么？** 130 s 时 |H| = 133 N·m·s，四台框架角
   `(329.7, −40.4, 148.9, −227.1)°`（无界、连续旋转），与初始构型差别很大：
   构型迁移不是"用完即回零"，而是平移到一个新的角动量状态。
2. **第二次机动前是否重新迁移配置？** 是。130–150 s 的保持阶段内 _H_ 先降到 47 N·m·s
   再回到 111 N·m·s，框架角 `g1` 由 329.7° 到 229.9°（约 100°）、`g2` 由 −40.4° 到
   +44.9°，即 B 组在两次机动之间继续调整构型，为反向机动重新预置角动量。
3. **第一次机动是否帮助或妨碍第二次？** 相对 A 组，B 组在第二次机动上仍有改善
   （0.387° → 0.040°），但**收益远小于第一次**（98% vs 90%，且绝对量已很小）。
   原因在数据里很清楚：回基础姿态是"俯仰向下"方向，而力矩盒在该方向有大量富余
   （机动窗口贴边比例仅 0.15/0.16），A 组自己就能完成。
   第一次机动并没有妨碍第二次：A、B 的 110–130 s 结果与 S00 完全一致（4.664°/0.096°），
   说明前段历史是确定性的，不存在"B 组迁移反而拖累后段"的证据。
4. **两次机动是否都获得收益？** 都获得，但收益幅度由"该机动方向的舵面能力缺口"决定，
   而不是由 CMG 是否迁移决定：上仰方向收益巨大，回到基准方向收益很小。

## 7. 阶段 3：P1 真实舵面执行器交叉验证（6 次运行）

| 场景 | A RMSE（P0 → P1） | B RMSE（P0 → P1） | P1 相对改善 |
|---|---:|---:|---:|
| S00 俯仰 +30° | 4.664° → **8.869°** | 0.096° → **0.169°** | −98.1% |
| S01 俯仰 −30° | 5.093° → **10.544°** | 0.152° → **0.151°** | −98.6% |
| S06 俯仰 +30° & 滚转 +20° | 4.915° → **8.701°** | 0.098° → **0.139°** | −98.4% |

- **A 组在 P1 下明显变差**（约 ×1.8）：P0 允许优化器在能力盒内直接指定总气动力矩，
  而 P1 必须用有界最小二乘舵偏去凑，再经过 `tau_s = 0.05 s` 一阶伺服与
  每步 ≤ `τs·δ̇max` = 3° 的指令钳位。A 组舵偏位置饱和比例达 0.25（S00），
  实际俯仰气动力矩 RMS 只有 4.24 N·m，仅是 B 组 9.37 N·m 的 45%。
- **B 组的收益在 P1 下保持**（0.169°/0.151°/0.139°，与 P0 同量级）。
  因此本实验**不属于**"P0 有收益、P1 无收益"的情形：收益不依赖理想力矩执行假设。
- P1 舵偏角速率饱和比例恒为 0：模型的伺服指令钳位（3°/步 = 15°/s）远严于
  `δ̇max = 60°/s`，因此**速率限幅不是约束**，真正起作用的限幅是位置限幅与伺服滞后。
  这一点与 P0 的"贴边比例"含义不同，两者分表统计、不混用。
- 期望力矩与实际力矩的差异（`|τa_cmd − τa_act|` RMS，俯仰轴）：
  A 0.03–0.07 N·m，B 2.47–2.60 N·m。B 更大是因为 B 的舵面指令变化更快、更大，
  受伺服滞后影响更明显；评价一律使用实际气动力矩 `tau_act`，不用指令值代替。

## 8. 求解可靠性与实时性（全部样本保留）

| | A 组 | B 组 |
|---|---|---|
| 平均求解耗时 | 0.017–0.158 s | 0.239–1.394 s |
| P95 求解耗时 | 0.025–0.341 s | 0.654–4.843 s |
| 满足 0.2 s 控制周期（P95 判据） | S02、S06-P1 满足，其余不满足 | 全部不满足 |
| fallback 比例 | 0.000–0.007 | 0.000–0.117（最大 S03） |
| 最大约束违反 | ≤ 4.4e-5 | ≤ 1.0e-2（S06-P1 单次） |

**实时性未满足**：B 组在 0.2 s 周期内不可实时求解；A 组只有在 227 变量的小规模下
P95 才偶尔落进 0.2 s。失败与 fallback 样本全部保留在 `metrics.json`
（`status_counts`、`fallback_steps`）与 `timeseries.csv`
（`status`、`fallback`、`iter_count`、`cpu_s`、`max_violation`）中。

A 组任务失败的归因（指导书 §13 要求）：**不是**求解失败（fallback ≈ 0、约束违反 1e-8 量级），
而是**气动能力不足**——P0 中机动窗口的三轴平均贴边比例达 0.12–0.67，
P1 中舵偏位置饱和达 25%（S00）。
因此不能把"未完成"直接归因于"没有 CMG"，也不能反过来把 A 的失败当成 CMG 有效的唯一证据。

- **所有场景 B 组都在机动前约 17–19 s 开始迁移构型**，不是机动开始后才动作；
  机动前累计框架行程 0.97–9.71 rad、框架角最大偏移 79°–556°（无界、连续旋转）。
- **角动量预置方向随任务方向改变**：S00 与 S01 的 `Hy` 分别为 +155.8 与 −156.1，
  S04（滚转）主要用 `Hz`（机动前 |H| 仅 15.9），S05（偏航）主要用 `Hz` 与 `Hx`

  不是人为设定：`A(gamma)` 在零构型下对俯仰轴给出最大刚度。
- **角动量储备 ≠ 瞬时力矩能力**：S03/S05/S06 的 |H| 峰值已达 158–163 N·m·s
  （满量程 200），但 σmin 掉到 1e-4 / 1e-5 / 0.18，仍能输出力矩——瞬时能力对方向高度
  各向异性（图 7 中"沿任务方向的瞬时力矩能力"在近奇异处出现尖峰与旁瓣），
  而各向同性的保证力矩 `σmin·γ̇max` 同时趋近 0。这就是图中把"能力"与"储备"分开画、
  并单独给出 σmin 的原因。
- **构型迁移本身不构成有效辅助的证据**：S02 中迁移发生了（提前 18.2 s），
  但 A 组本来就能完成（0.845° 峰值误差），因此不能称为"必要辅助"。
- **角动量管理不保守（能力边界之外的另一个问题）**：B 组在 90–150 s 内多次把 |H| 推到
  158–163 N·m·s（满量程 200）再释放，例如 S07 的 |H| 时序为
  25 → 88 → 147 → 158 → 50 → 158 → 49 → 133 → 103 → 71 → 47 → 111 N·m·s。
  由于本配置链的框架角是无界连续变量，优化器会反复穿越高角动量状态而不保留储备；
  这是"能完成任务"与"保留裕度"之间的取舍，本报告如实记录，未为此调整任何权重
  （指导书 §14.4 禁止为制造迁移而改目标函数）。

## 10. 多种子稳健性

扰动模型的正弦相位由种子决定（`seed_randomize: true`），A/B 同种子。
S00/S01/S06 各加 seed 1、2（共 3 个配对种子，12 次追加运行）：

| 场景 | seed | A RMSE | B RMSE | 相对改善 |
|---|---|---:|---:|---:|
| S00 | 0 / 1 / 2 | 4.664 / 4.664 / 4.664° | 0.096 / 0.095 / 0.097° | −97.9% / −98.0% / −97.9% |
| S01 | 0 / 1 / 2 | 5.093 / 5.093 / 5.093° | 0.152 / 0.152 / 0.152° | −97.0% / −97.0% / −97.0% |
| S06 | 0 / 1 / 2 | 4.915 / 4.915 / 4.915° | 0.098 / 0.098 / 0.098° | −98.0% / −98.0% / −98.0% |

解读（严格遵守指导书 §13 最后一条）：三个种子的结果几乎完全相同，说明
**结论不是某个特定扰动相位造成的偶然**，但**这也只是 3 个配对样本**，
不构成统计显著性；A/B 差异的成因是能力缺口这个结构性因素，而不是扰动实现。
若要给出统计结论，需要更多种子、更多初始偏差与更多飞行条件的配对实验。

## 11. 结论

1. **在本实验条件下，增加 CMG 并允许其参与控制，显著改善所有 7 个 P0 场景的姿态机动执行**
   （机动窗口 RMSE 降低 79.6%–99.8%），且在 P1 真实舵面执行器下
   （S00/S01/S06）同样成立（97.0%–98.6%）。
2. **收益的大小由该机动方向的舵面能力缺口决定**，而不是由"是否发生迁移"决定：
   上仰（S00/S01/S03/S06）、滚转（S04）、偏航（S05）缺口大、收益大；
   回基础姿态（S07 第二次）、小幅俯仰（S02）缺口小、绝对收益小。
3. **机制证据成立**：B 组在所有场景都提前约 17–19 s 迁移构型，并在机动前形成
   与任务方向对应的角动量预置（S00 与 S01 的 `Hy` 严格反号）。
   但迁移本身不构成"有效辅助"的充分条件（S02），需结合机动期间的实际 CMG 力矩与
   角动量变化解释，本报告已逐场景给出。
4. **能力边界如实报告**：S03（俯仰 45°）与 S05（偏航 30°）出现 σmin → 0 的近奇异、
   |H| 接近满量程、框架速率饱和 12.4% / 3.3%、能力盒贴边 0.97 / 0.80，
   B 组仍未完全消除跟踪误差。这两个场景是"舵面 + 本 CMG"的联合能力边界。
5. **A 组未完成任务的原因已归因**：不是求解失败、不是日志/实现问题，而是气动力矩能力
   不足（P0 机动窗口三轴平均贴边比例 0.12–0.67，P1 舵偏位置饱和 25%）。
   不能把失败全部归给"没有 CMG"。
6. **实时性未满足**：B 组平均求解 0.24–1.39 s、P95 最高 4.84 s，远超 0.2 s 控制周期；
   当前闭式 NLP 求解器不是可实时实现的方案。
7. **舵面负担的变化必须结合跟踪结果解释**：B 组舵面 RMS 在多轴/俯仰任务中高于 A 组，
   原因是 A 组被能力盒限制住而无法真正执行机动；若只看"RMS 更低"这一项而忽略跟踪，
   会得到相反的错误结论。
8. **本轮对照是匹配惯量的算法对照**，不是完整硬件质量/惯量级工程对比；
   仅此一次（每格 1–3 个种子）的仿真不能称为统计显著。

## 14. 附：求解速度优化（本轮追加工作）

原实现的 B 组求解耗时（均值 0.24–1.39 s、P95 最高 4.84 s）远超 0.2 s 控制周期。
后续在**不改变 A/B 对照定义**的前提下做了三层优化，完整报告见
`docs/torque_gap/mpc_solver_speedup.md`，数据见
`results/torque_gap_mpc_speed/` 与 `results/torque_gap_no_cmg_comparison_{fast,rti}/`。

| 后端 | B 组机动 RMSE（8 场景均值） | 均值耗时 | P95 | 最坏步 | 进入 0.2 s 的场景 |
|---|---|---:|---:|---:|---:|
| baseline（本文主体结果） | 0.733° | 781 ms | 2973 ms | 8388 ms | 0/8 |
| Tier 1：同求解器改用法（tol、采纳可行解、保留热启动） | 0.740° | 252 ms | 648 ms | 1477 ms | 0/8 |
| Tier 3：HPIPM 实时迭代（GN-QP，12 次/步） | 1.821° | 79 ms | 128 ms | 250 ms | 8/8 |
| **Tier 3+：HPIPM + δγ/δω 信赖域** | **0.740°** | **108 ms** | **139 ms** | **173 ms** | **8/8** |

要点：

1. **本文的 A/B 结论方向在各后端下都成立**：A 组均值 6.26–6.28° 不变，B 组
   0.73°（IPOPT）/ 0.740°（RTI+信赖域），8 个场景全部仍是"B 组跟踪显著改善"。
   求解器的差异体现在**能力受限场景的收益幅度**：纯 RTI 会把 S03 的相对改善从
   −79.6% 压到 −22.6%（长视界非线性规划能力本身是近奇异工况收益的一部分来源）；
   加上信赖域后回到 −77.8%，与 IPOPT 基本一致。因此报告应以
   **RTI+信赖域**作为实时实现的主结果，纯 RTI 的数据只作为"线性化敏感性"的说明。
2. Tier 1（`fast` profile）是零风险收益：约 3x 提速、跟踪不降；
   `results/torque_gap_no_cmg_comparison_fast/` 是完整重跑的 34 次矩阵。
3. 纯 RTI 把每一步压进 0.2 s 周期，但能力受限场景（S03/S05）跟踪退化 2–4x：
   长视界上的 GN 线性化把周期函数 `A(γ)` 当常数、并允许线性模型"无限攒角动量"，
   在 σmin→0 处失效。加一个 `|δγ| ≤ 0.5 rad`、`|δω| ≤ 1 rad/s` 的硬信赖域后
   （速度报告 §2.1），**S03 2.24→2.43°、S05 3.20→3.11°**，其余场景不变或更好，
   8 场景均值 0.740° 与 IPOPT 的 0.733° 只差 0.9%，而**每一步（最坏 173 ms）
   都在 0.2 s 周期内**。P1 交叉验证中 S00/S01 也更好，唯一明显回退是
   **S06 P1（0.139→0.652°）**，已在速度报告中标注。
4. 缩短预测视界（Tier 2）**不可行**：视界 23.2 s → 9.2 s 虽快 7.5x，但
   B 组 RMSE 全面崩塌（S00 0.096→2.31°）。因为 B 组的构型迁移平均提前
   17–19 s 开始，9 s 视界在物理上看不到需要预置的机动——**长视界是
   本方案预置机制的功能性前提**，不是求解器的浪费。
5. 去掉冗余的四元数范数等式（`quat_norm: n0`）可再提速 1.2–3.8x 且多数场景精度
   略升，但偏航轴退化（S05 3.20→4.61°），因此仅作为可选开关，默认不变。
